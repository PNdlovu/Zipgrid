## Why This Document Exists

Every founder who has suffered through painful rewrites will recognise the pattern:

1. Build fast with good intentions
2. Ship something that works
3. Realise a core assumption was wrong (currency, compliance, architecture, UI system)
4. Spend weeks reverting, refactoring, or rebuilding from scratch
5. Lose momentum, team morale, and sometimes the company

This checklist is the antidote. Every item below represents a mistake that causes rewrites. Check every box before writing a single line of application code.

## SECTION A — Architecture

| # | Check | Why It Matters | Status |
|---|-------|---------------|--------|
| A1 | DDD bounded contexts are defined and documented (see 3.12) | Mixing domains causes spaghetti code that is impossible to untangle | ✅ Done |
| A2 | Monorepo structure is agreed (apps/ + packages/) | Shared types prevent drift between web and mobile | ✅ Done |
| A3 | Domain event bus is designed (not direct cross-domain imports) | Cross-domain coupling prevents future service extraction | ✅ Done |
| A4 | Region abstraction layer is built before any country-specific code | Hardcoded UK logic = complete rewrite for EU/US | ✅ Done |
| A5 | API is versioned from day 1 (/api/v1/) | API breaking changes break existing mobile app users | ✅ Done |
| A6 | All services are stateless (no in-memory state) | Stateful services cannot scale horizontally | ✅ Done |
| A7 | Database migrations are backward-compatible | Breaking migrations cause zero-downtime deploy failures | ✅ Done |
| A8 | OCPP service is a separate process (not inside Next.js) | WebSocket connections cannot live in serverless functions | ✅ Done |
| A9 | AI service is a separate process (Python, isolated compute) | LLM load spikes cannot affect the main API | ✅ Done |
| A10 | All domain services expose a public API contract (index.ts) | Without this, every module becomes tangled over time | ✅ Done |

## SECTION B — Database & Data

| # | Check | Why It Matters | Status |
|---|-------|---------------|--------|
| B1 | ALL monetary values stored as integers (pence/cents) | Floating-point arithmetic causes financial audit failures | ✅ Done |
| B2 | PostGIS extension enabled for spatial queries | Geo-search without PostGIS is 100× slower at scale | ✅ Done |
| B3 | Row-Level Security (RLS) enabled on all user data tables | Without RLS, a bug can leak one user's data to another | ✅ Done |
| B4 | Audit log is append-only (REVOKE UPDATE/DELETE) | Mutable audit logs are legally useless | ✅ Done |
| B5 | Data residency confirmed (Amsterdam eu-west for UK + EU) | Wrong data residency = GDPR violation before you launch | ✅ Done |
| B6 | Retention schedules documented and automated (pg_cron) | Holding data beyond retention = GDPR violation | ✅ Done |
| B7 | No unbounded queries — all list endpoints paginated | Unpaginated queries bring down the DB at scale | ✅ Done |
| B8 | Indexes on all foreign keys and frequently filtered columns | Missing indexes = query timeouts at 100k rows | ✅ Done |
| B9 | session_meter_values uses BIGSERIAL (not UUID) for PK | UUID PKs on high-frequency inserts cause index fragmentation | ✅ Done |
| B10 | Pre-migration DB snapshot automated before every migration | One bad migration can destroy production data | ✅ Done |

## SECTION C — Security

| # | Check | Why It Matters | Status |
|---|-------|---------------|--------|
| C1 | JWT access tokens: 15-minute TTL | Long-lived tokens = stolen token = long-window attack | ✅ Done |
| C2 | Refresh tokens: single-use rotation | Reusable refresh tokens = token theft goes undetected | ✅ Done |
| C3 | All inputs validated with Zod before processing | Unvalidated input = SQL injection, XSS, type errors | ✅ Done |
| C4 | No raw SQL string interpolation anywhere | String interpolation = SQL injection | ✅ Done |
| C5 | Gate codes AES-256-GCM encrypted in database | Plain-text gate codes = unauthorised property access | ✅ Done |
| C6 | DMARC policy set to `p=reject` | Without DMARC, anyone can send email from your domain | ✅ Done |
| C7 | Cloudflare WAF active before any public traffic | First wave of traffic includes scanners and bots | ✅ Done |
| C8 | Rate limiting on all API routes (100 req/min authenticated) | No rate limiting = trivial DDoS or brute-force | ✅ Done |
| C9 | AI system prompt loaded from env (not user input) | User-controlled system prompt = full prompt injection | ✅ Done |
| C10 | AI tool allowlist enforced | No allowlist = AI can call any function in the codebase | ✅ Done |
| C11 | OCPP charger credentials hashed (not plain text) | Plain-text credentials = charger hijacking | ✅ Done |
| C12 | npm audit in test runner — blocks on critical vulns | Shipping with known critical vulnerabilities = liability | ✅ Done |
| C13 | No secrets in source code or .env files committed | Committed secrets = public breach (GitHub scans these) | ✅ Done |
| C14 | PCI-DSS SAQ A self-assessment completed | Processing payments without PCI compliance = fines | ✅ Done |
| C15 | External pen test commissioned before launch | Self-assessment misses what a human attacker finds | 🔲 Pre-launch |

## SECTION G — AI Safety

| # | Check | Why It Matters | Status |
|---|-------|---------------|--------|
| G1 | System prompt loaded from environment (never from user input) | User-controlled system prompt = jailbreakable | ✅ Done |
| G2 | Prompt injection detection on all user inputs | Common attack vector — easy to implement, easy to miss | ✅ Done |
| G3 | Tool allowlist enforced (ALLOWED_TOOL_NAMES) | No allowlist = AI can call any function | ✅ Done |
| G4 | Tool parameter ownership validation (can't act on other user's data) | Without this, AI can be tricked into modifying another user's session | ✅ Done |
| G5 | Confidence thresholds enforced (< 0.60 = reject) | Low-confidence AI actions cause wrong bookings, wrong charges | ✅ Done |
| G6 | Payments and bookings ALWAYS require confirmation | Even 0.99 confidence should not auto-charge a user | ✅ Done |
| G7 | AI agent cannot execute shell commands | Direct code execution = full system compromise | ✅ Done |
| G8 | Voice transcripts retained max 30 days then deleted | Indefinite voice retention = GDPR privacy risk | ✅ Done |
| G9 | AI responses monitored for hallucination patterns | Hallucinated prices or charger specs = customer disputes | 🔲 Phase 2 |
