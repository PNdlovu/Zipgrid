## 1. Executive Summary

Zipgrid is a UK-first EV charging ecosystem platform that leapfrogs dated incumbents by combining four capabilities no single competitor offers today:

1. **P2P / host-to-driver charging marketplace** — private homes and businesses become reservable charge points
2. **Voice-first UX** — natural language control of chargers, bookings, and account management
3. **Agentic AI automation** — the platform acts autonomously: schedules, optimises, troubleshoots, and books technicians
4. **Integrated marketplace** — hardware, accessories, and certified installer services in one place

The platform serves three primary user types: **homeowners** with idle chargers, **small businesses** with parking bays, and **EV drivers** seeking affordable guaranteed charging. A fourth supply-side segment — **installers and hardware vendors** — participates via the marketplace.

Stack: **Next.js 15** (App Router) · **PostgreSQL + PostGIS** · **OCPP WebSocket service** · **LangChain + RAG (voice/AI)** · **Stripe Connect** · **Mapbox GL JS**. Clean white background UI with true black dark mode.

### MODULE E — Agentic AI Layer

#### E1. What "Agentic" Means in Zipgrid
The AI layer does not just answer questions. It executes multi-step workflows autonomously on behalf of the user, with confirmation gates where money or access is involved.

```
User Goal → Agent Plan → Tool Calls → Result → Confirmation (if needed) → Execution
```

#### E2. Agentic Workflows — Homeowner
| Trigger | Agent Action |
|---------|-------------|
| Charger fault detected (OCPP error code) | Notify host → diagnose fault type → suggest fix → if hardware fault: search marketplace for nearest available installer → present booking options → confirm with host → book |
| Energy tariff API shows tomorrow's cheapest window | Auto-schedule charging session without user input (within user-set parameters) |
| Session ends at 3am, cheap tariff ends at 6am | Top up battery to user's preferred % automatically |
| Monthly earnings below threshold | Suggest pricing adjustment based on nearby comparable listings |
| Charger approaching 2-year service interval | Remind host + offer marketplace installer booking |

#### E3. Agentic Workflows — Driver
| Trigger | Agent Action |
|---------|-------------|
| Driver opens app with low battery (< 20%) | Proactively surface nearest available charger + pre-fill booking form |
| Route entered in navigation | Auto-suggest corridor charging stops along route |
| Session idle fee imminent | Push alert + voice notification *"Your car is done — move it to avoid fees"* |
| Regular commuter pattern detected | Suggest recurring booking at preferred listing |

#### E4. Agentic Workflows — SMB Host
| Trigger | Agent Action |
|---------|-------------|
| Utilisation below 30% for 2 weeks | Suggest pricing reduction + promotional options |
| Charger offline for > 1 hour | Alert host + suggest technician booking |
| Demand spike during peak hours | Suggest enabling dynamic surge pricing |
| Customer leaves negative review | Draft response suggestion for host approval |

#### E5. AI Stack
- **Orchestration**: LangChain (agent chains, tool calling, memory)
- **LLM**: OpenAI GPT-4o (reasoning, NLP, response generation)
- **RAG Knowledge Base**: Platform docs, tariff data, charger manuals, UK regulations — stored in vector DB
- **Vector DB**: Pinecone (managed) or Weaviate (self-hosted for cost at scale)
- **Embedding model**: OpenAI text-embedding-3-small
- **Memory**: Short-term (session context) + long-term (user preference store in PostgreSQL)

## 6. Design Principles

| Principle | Implementation |
|-----------|---------------|
| **White background, true black dark mode** | Default: clean white (#FFFFFF). Dark mode: pure black (#000000) not dark navy. No grey background surfaces in dark mode. |
| **Voice-first, touch-second** | Every key action must be completable by voice. Touch is a fallback, not the primary interaction model. |
| **Progressive disclosure** | Show simple options first. Advanced settings are available but not foregrounded. |
| **Zero friction for common tasks** | Booking a charger: ≤ 3 taps or 1 voice command. Starting a session: QR scan or PIN. Stopping: 1 tap. |
| **Transparency always** | Pricing breakdowns always shown before payment. Commission always visible in host earnings. |
| **Accessible by default** | WCAG 2.1 AA minimum. Voice interaction inherently improves accessibility. |

### MODULE I — In-Platform Wallet

The Zipgrid Wallet is a pre-loaded credit balance within the platform. Drivers top up from a card and spend on sessions. Wallet credit also receives loyalty rewards redemptions, referral bonuses, and promotional credits — creating a closed loop that increases retention and reduces per-transaction payment friction.

#### I1. Driver Wallet Features
- [ ] Wallet balance displayed on home screen and booking flow
- [ ] Top up wallet with card, Apple Pay, or Google Pay (minimum £5, maximum £500)
- [ ] Auto top-up: set a threshold (e.g. top up £20 when balance falls below £5)
- [ ] Use wallet balance to pay for bookings (takes precedence over saved card if balance is sufficient)
- [ ] Split payment: wallet balance + card for shortfall
- [ ] Wallet transaction history (top-ups, session payments, rewards redemptions, refunds)
- [ ] Refunds credited back to wallet by default; option to refund to original card
- [ ] Wallet balance is non-transferable between users

#### I2. Wallet — Backend & Financial
- [ ] Stripe Customer Balance (pre-load model) — Zipgrid holds float; Stripe manages ledger
- [ ] Wallet funds are ring-fenced — never co-mingled with host payout funds
- [ ] Unused wallet balance refundable to original payment method on account closure
- [ ] Float interest modelled in revenue projections (see 1.5 Revenue Model v0.2)
- [ ] HMRC / FCA considerations reviewed — wallet is pre-payment, not e-money (legal review required)

### MODULE K — Emergency Charging Mode

Emergency Charging is a distinct mode activated when a driver's battery is critically low. It bypasses the standard booking flow to surface the fastest available charging option within the driver's remaining range.

#### K1. Driver Emergency Flow
- [ ] "Emergency Charging" button visible on home screen and map (prominent, red)
- [ ] Tap activates emergency mode — app requests current location and prompts for current battery %
- [ ] App calculates maximum driveable range (battery % × vehicle range × weather penalty factor)
- [ ] Map instantly recentres showing only listings reachable within that range
- [ ] Listings ranked by proximity, not price — availability is the primary sort
- [ ] Platform fee waived for emergency sessions (configurable — default: waived)
- [ ] Emergency booking request sent to host with "SOS" flag — host sees priority alert
- [ ] Session starts immediately upon host acceptance (no standard booking window)
- [ ] If no hosts accept within 5 minutes: platform sends secondary alert to next 5 nearest hosts

#### K2. Host Emergency Notifications
- [ ] Push notification: "⚡ Emergency charging request — driver has [X]% battery, [Y] miles away. Accept?"
- [ ] Accept/decline buttons directly in notification (no need to open app)
- [ ] Host earns an "Emergency Host" badge after 3 accepted emergency sessions
- [ ] Emergency sessions count toward Superhost eligibility (weighted 2×)

#### K3. Safety & Fallback
- [ ] If no Zipgrid host available: app shows nearest public chargers (Zap-Map data via OCPI)
- [ ] Emergency mode auto-deactivates after session starts or driver manually dismisses
- [ ] All emergency sessions flagged in admin dashboard for review

### MODULE L — Multi-Stop Trip Planner & AI Concierge

The Trip Planner allows drivers to enter a destination and have the AI plan, optimise, and book all required charging stops along the route — in a single interaction.

#### L1. Trip Planning Flow
- [ ] Driver enters destination (text or voice: "Plan my trip to Manchester tomorrow")
- [ ] App requests: current battery %, departure time, vehicle range preference (arrive at 20% minimum)
- [ ] Route calculated via Mapbox Directions API
- [ ] AI calculates charging stops needed based on: vehicle range, battery level, weather penalty, traffic delay estimate
- [ ] For each charging stop:
  - Corridor search (ST_DWithin on route linestring)
  - Filter to compatible plug types
  - Filter to available slots matching estimated arrival time window
  - Rank by: price, rating, proximity to route
- [ ] Presents full trip plan: Depart → [Stop 1: Charger, arrival time, cost estimate] → [Stop 2…] → Arrive
- [ ] Driver reviews plan, can swap any stop with alternatives
- [ ] "Book all stops" — confirms all bookings and places payment holds in one action
- [ ] Trip plan saved to "My Trips" with live progress tracking

#### L2. AI Concierge Suggestions
- [ ] For each charging stop: suggest nearby restaurant, café, or attraction (Google Places API)

## MODULE T — Smartwatch & Wearable UX

*Added in Planning Baseline v2.2 — September 30, 2026*

> The screen becomes optional. The wrist becomes the interface.

Most competitors think: **Phone App → Charger.**
Zipgrid thinks: **Voice + Agent → Any Device → Charging Outcome.**

The smartwatch surface is not a miniaturised version of the phone app. It is purpose-built for the three moments where a wristwatch interaction beats a phone every time: **urgent alerts, one-tap confirmations, and ambient awareness.**

---

### T1. Driver Smartwatch Features

#### T1.1 One-Tap Emergency Charge
**Trigger:** Battery alert fires (SoC < threshold set in user_preferences)  
**Watch interaction:**
```
⚡ Battery at 12%
  [Find charger now]   [Dismiss]
```
Single tap → AI agent activates, searches within driveable range, presents nearest available listing.  
Second tap → Confirm booking.  
No phone needed.

**Implementation:** Push notification via FCM → watch companion app. Booking confirmed via AI service. Watch vibrates on confirmation.

#### T1.2 Arrival Assistant
**Trigger:** Driver is within 500m of their booked listing  
**Watch notification:**
```
🟢 Charging bay ready
  Nexus Coworking · Bay 4
  Walk 50m ahead · Gate code: 4471
  [Navigate]
```
No unlocking phone. No opening app. The watch surfaces exactly what the driver needs at the exact moment they need it.

#### T1.3 Session Live Tile / Complication
**While charging:** Live tile shows:
- Energy charged (kWh)
- Current cost (£x.xx)
- Estimated finish time
- SoC percentage

Watch face complication shows a single progress ring (0–100% charge target).

#### T1.4 Charging Complete
**Trigger:** Session ends (OCPP StopTransaction received)  
**Watch notification:**
```
✅ Charging complete
  26.4 kWh · 92% · £8.24
  231 miles range
  [Done]   [Extend stay]
```
If idle fee grace period is active, a countdown timer appears. Tap "Extend stay" to pay idle fee directly from wallet.

#### T1.5 Queue / Idle Fee Warning
**Trigger:** High demand detected at listing OR idle fee grace period starting  
**Watch notification:**
```
⏱ High demand nearby
  Move vehicle within 15 min
  to avoid idle fees
  [OK — I'm on my way]
```
Confirmatory tap clears the alert. No tap = escalating vibration at 10 minutes and 5 minutes.

#### T1.6 Family Safety Ping
**Feature:** Trusted contacts (set in profile) receive a watch notification when the driver arrives at their charging destination.  
```
✅ [Name] arrived safely
  Nexus Coworking, Manchester
  Session started · 09:02
```
Simple. No location tracking app required. The session arrival triggers the ping automatically.

### T3. Technical Implementation Notes

**Platform:** Apple Watch (watchOS 7+) via WatchKit / SwiftUI companion; Wear OS via Jetpack Compose Wear. Delivered as extensions of the React Native Expo mobile app.

**Watch actions:** Approve/decline booking request buttons use FCM notification action categories. The action POST request is made from the mobile app in background when the user taps the watch button.

- `WatchNotificationPayload` — typed in `packages/types/src/ai.ts` (see migration 016)
- `WearableSession` — live session state for watch complication

## MODULE U — AI Commute Agent

*Added in Planning Baseline v2.2 — September 30, 2026*

> The AI that manages your daily charging before you even think about it.

The AI Commute Agent is the highest-retention feature Zipgrid will build. Once a driver uses it for 2 weeks, it becomes a daily habit. It turns Zipgrid from an app people open when they need to charge into a background service they rely on without conscious effort.

---

### U1. Core Capability — Commute Pattern Learning

**How it works:**

1. **Pattern detection:** The agent analyses booking and session history over 2+ weeks  
2. **Pattern confirmation:** Agent surfaces a suggestion to the driver:  
   > "I've noticed you charge at Nexus Coworking on weekday mornings. Want me to handle that automatically?"  
3. **Driver enables it:** One tap / one voice command  
4. **Ongoing operation:** The agent manages the commute charging routine without further input

**What the agent monitors:**
- Home location (from `user_preferences.home_lat/lng`)
- Work location (from `user_preferences.work_lat/lng`)
- Typical departure time (learned from booking start times)
- SoC at start of typical commute (learned from session data)
- Preferred listings and connectors (learned from booking history)
- Current tariff rates (Octopus Agile API or flat rate)

---

### U2. Proactive Scheduling

**Scenario A — Tomorrow's commute:**
At 21:00 the night before a typical work day, the agent checks:
- Is the car likely to need charging? (estimated SoC based on typical usage)
- What is the cheapest 3-hour window tonight on the driver's tariff?
- Is the driver's preferred home charger available?

If yes → agent schedules the charge, confirms via notification.  
Driver receives:
```
🔋 Commute charge scheduled
  Tonight 02:00–05:00 · 7.8p/kWh
  Tesla → 85% SoC by 06:30
  Saves ~£4.20 vs charging now
  [OK]   [Change time]   [Skip tonight]
```

**Scenario B — Away from home routine (workplace charge needed):**
If the overnight home charge is insufficient for the next day's trip:
```
⚡ Suggesting a morning charge
  Tomorrow: 94 miles estimated
  Current SoC: 61% (~210 miles)
  You're fine — but I'll keep an eye on it.
```
Or:
```
⚠️ Long journey tomorrow
  I've pre-booked Nexus Coworking
  for 08:00 as a top-up
  ~£3.40 estimated · [Confirm]   [Cancel]
```

---

💡 Price alert

### U5. Privacy & Control

The AI Commute Agent is **opt-in only** and requires explicit consent in `user_preferences.ai_auto_schedule_enabled`.

Driver controls:
- Enable / disable entirely (voice: "Zipgrid, stop managing my charging")
- Pause for a set period ("Skip this week — I'm on holiday")
- Override any specific scheduled charge
- View all agent decisions in a transparent log (`/profile/ai-history`)
- Delete all learned patterns and start fresh

**Data used:** Session history, booking history, SoC data from OCPP, tariff rates (external API). No location tracking beyond what the driver has already provided in preferences.
