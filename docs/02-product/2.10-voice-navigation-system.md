## 1. Voice-First Philosophy

Voice is not a feature. It is an interface. Every critical action in Zipgrid is completable by voice — on mobile, in a car via CarPlay/Android Auto, or on desktop in a browser.

**The goal:** A driver with 10% battery, in a car, in the rain, should be able to find and book emergency charging without touching their phone screen.

**The standard:** If a user has to touch the screen to do something important, voice has failed.

---

## 2. Technical Stack

### Browser Voice (Web)
- **Primary:** Web Speech API (browser-native, no audio leaves the device)
- **Fallback:** OpenAI Whisper API (when Web Speech is unavailable or accuracy is poor)
- **Response TTS:** Web Speech Synthesis API (browser-native, no latency)
- **Premium TTS (optional):** ElevenLabs voice (warmer, more natural — available on paid tiers)

### Mobile Voice (React Native)
- **iOS:** AVSpeechSynthesizer (native) + SFSpeechRecognizer (native STT)
- **Android:** Android SpeechRecognizer API (native STT)
- **Fallback:** Whisper API (same as web)
- **CarPlay:** AVSpeechSynthesizer via CarPlay entitlement

### Intent Engine
- **Text → Intent:** GPT-4o via LangChain (context-aware, multi-turn)
- **Intent → Action:** LangChain tool calling with ownership validation
- **Context:** User's current session, bookings, location, vehicle, preferences injected per request

## 4. Multi-Turn Conversation Memory

Voice sessions maintain conversational context for the duration of a session.

```
User: "Find me a charger near Waterloo"
Zipgrid: "I found 4 chargers within half a mile. The closest is Sarah's at 0.2 miles, £0.32/kWh."

User: "Is it available tomorrow at 10?"
// AI remembers context — "it" = Sarah's listing
Zipgrid: "Yes, tomorrow at 10am is open. Want me to book it?"

User: "Yes, for 2 hours"
// AI remembers booking intent + listing
Zipgrid: "Booking Sarah's driveway for tomorrow at 10am, 2 hours, estimated cost £5.18. Shall I confirm?"

User: "Confirm"
Zipgrid: "Done. Booking confirmed. Your arrival code is ZG-8472."
```

## 5. Voice UI Components

### Microphone Button States

```
Idle:          Microphone icon, no animation
Listening:     Pulsing green waveform animation
Processing:    Spinning indicator
Responding:    Speaking animation (sound wave)
Error:         Brief red flash, reset to idle
```

### Visual Transcript

While speaking, transcript appears word-by-word in the voice overlay. This gives feedback that the system is hearing correctly and allows the user to see if recognition is wrong before completion.

### Confidence Display

If the system is not sure what was said:
- Display the transcript: *"I heard: 'Book a charger for Tuesday 10pm' — is that right?"*
- Two options: **Yes, that's right** | **Try again**

Never silently execute a low-confidence interpretation.

## 8. Accessibility — Voice as Primary Interface

For users with motor impairments or visual impairment, voice is the primary interface, not an enhancement. All voice commands therefore must:

- Have no time pressure (no "say your command within 3 seconds" pressure)
- Never require visual confirmation to complete (pure voice confirmation path available)
- Support correction: *"No, change that to 9am not 10am"*
- Support cancellation at any point: *"Cancel"* or *"Never mind"* always works
- Never produce voice responses longer than 3 sentences without a natural pause

These rules align with WCAG 2.5.3 (label in name) and WCAG 3.3.4 (error prevention for legal/financial).

### Supported Languages at Launch

| Language | Locale | Availability |
|----------|--------|--------------|
| English (UK) | `en-GB` | ✅ Launch |
| English (Ireland) | `en-IE` | ✅ Launch (same prompts) |
| Dutch | `nl-NL` | ✅ Phase 3 (Netherlands expansion) |
| German | `de-DE` | ✅ Phase 3 (Germany expansion) |
| French (Belgium) | `fr-BE` | ✅ Phase 3 (Belgium expansion) |
| French (France) | `fr-FR` | ✅ Phase 3 |
| Spanish | `es-ES` | Phase 4 |
| Polish | `pl-PL` | Phase 4 (large UK EV driver community) |
| Romanian | `ro-RO` | Phase 4 (large UK EV driver community) |

**Why Polish and Romanian at Phase 4:** A significant proportion of UK EV drivers are from Polish and Romanian communities. These locales represent meaningful UK market segments, not just EU expansion markets.

### How Multi-Language Voice Works

The Web Speech API detects the browser/device language automatically and passes the BCP-47 locale code to the intent parser. GPT-4o processes the intent from the user's native language and responds in kind. The tool call JSON is language-agnostic — the action taken is identical regardless of language.

```
User (Dutch): "Vind een laadpaal bij mij in de buurt"
             ↓
STT → transcript: "Vind een laadpaal bij mij in de buurt"
             ↓
IntentParser(language="nl-NL") → tool call: find_charger({location: "current"})
             ↓
Response (Dutch): "Ik heb 4 laadpalen gevonden in uw buurt.
                   De dichtstbijzijnde is op 0,3 km afstand."
             ↓
TTS (Dutch): Web Speech Synthesis with lang="nl-NL"
```

### Language Detection Priority

1. Explicit locale in the API request (from app settings)
2. Browser `navigator.language`
3. Web Speech API recognition language
4. Default: `en-GB`

Users can override their language in Settings → Language. Once set, all voice interactions and TTS responses use that language consistently.

## 10. Accessibility-First Voice Commands

*Added in Planning Baseline v2.3 — September 30, 2026*

Voice is not just a convenience feature. For drivers with motor impairments, visual impairment, or cognitive differences, voice is the **primary interface** — not a shortcut.

### Accessibility Filter Commands

| Voice Command | Action |
|--------------|--------|
| *"Find a wheelchair accessible charger near me"* | Filters `access_wheelchair = true` |
| *"Find a step-free charger near Waterloo"* | Filters `access_step_free = true` |
| *"Find a covered charger — I can't walk far in the rain"* | Filters `access_covered = true` |
| *"Find a charger with a toilet nearby"* | Filters `access_toilet_nearby = true` |
| *"I'm travelling with my kids — find a family-friendly charger"* | Family mode: filters `access_family_friendly = true`, shows POI panel |
| *"Find a charger near a café for my children"* | Same as above |
| *"Find a lit charger — it'll be dark when I arrive"* | Filters `access_lighting = true` |
| *"Accessible chargers only please"* | All accessibility filters active |

### Family Mode

When "family mode" is activated (voice or toggle):
- Map shows only listings with `access_family_friendly = true` OR listings with `listing_pois` entries for restaurants/play areas/cafés within 200m
- Listing cards show nearby POI icons: 🚻 🍕 🛝
- AI trip planner factors minimum session duration to ensure enough time at amenities
- Listing health agent flags listings near family POIs that don't have `access_family_friendly` set

### Voice Accessibility Rules (Permanent Standards)

These rules apply to ALL voice interactions — not just accessibility mode:

- **No time pressure** — users are never asked to respond within a countdown. No "say your command in 3 seconds" pressure.
- **Pure voice confirmation path** — every money or access action can be confirmed by voice alone: *"Yes"* / *"Confirm"* / *"Go ahead"*. No screen touch required.
- **Correction without restart** — *"No, change the time to 9am"* / *"Actually, cancel that"* — multi-turn correction works at any point.
- **Slow speech mode** — users can set TTS rate in preferences (`user_preferences.preferred_tts_rate`). Default 1.05×; recommended for accessibility: 0.85×.
- **Never read out more than 3 sentences before pausing** — agent always pauses for confirmation or "tell me more" on longer responses.
- **Screen reader compatible** — all voice overlay elements have `aria-live` regions; transcript is exposed to screen readers.
