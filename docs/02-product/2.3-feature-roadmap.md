---

## Roadmap Philosophy

> "Don't build what incumbents have. Build what they cannot build."

Every feature decision is filtered through the leapfrog lens:
- Does it extend the **voice-first** advantage?
- Does it deepen the **agentic AI** layer?
- Does it grow the **P2P marketplace network**?
- Does it serve **homeowners or SMBs** better than any competitor?

If the answer is no to all four, it moves to the parking lot.

## PHASE 1 ADDITIONS — Foundation (Month 0–6)

### 🆕 Emergency Charging Mode (N3 — promoted to Phase 1)
Emergency charging is a safety feature that must exist at launch. Without it, a driver with a critically low battery has no recourse on the platform.

- [ ] "Emergency Charging" SOS button on map home screen
- [ ] Range-limited charger filter (calculates max reachable distance from current battery %)
- [ ] Vehicle weather range penalty applied to emergency range calculation
- [ ] Emergency booking request sent to nearest available hosts with SOS alert
- [ ] Host accept/decline directly from push notification
- [ ] Session starts immediately on host acceptance (bypasses standard booking window)
- [ ] Fallback: shows nearest public chargers via Zap-Map OCPI data if no Zipgrid host available
- [ ] Platform fee waived on emergency sessions (configurable in admin)
- [ ] Emergency sessions flagged in admin dashboard

### 🆕 Safety Scoring — Core (N8 — Phase 1)
Safety Score is a trust signal. Displaying it from day one on every listing anchors the platform's safety positioning.

- [ ] Safety Score calculation job (nightly pg_cron)
- [ ] Score components: charger age, RCD confirmation, installer-confirmed, OCPP fault rate, incident history
- [ ] Score displayed on listing card (shield icon + number) and detail page (full breakdown)
- [ ] Auto-pause listing if score drops below 50
- [ ] Host portal: score breakdown + improvement suggestions
- [ ] Score updates reflected within 24 hours of a fault or incident

### 🆕 Resolution Centre UI — Core (N10 — Phase 1)
Disputes happen from day one. The UI must exist at launch — even if volume is low — so users have a clear, trusted process.

- [ ] "Report a problem" CTA on every completed booking
- [ ] Category selection: session fault / property damage / billing / driver behaviour / other
- [ ] Description + evidence upload (photos, video, documents — up to 50 MB)
- [ ] Platform-hosted mediation thread (no direct user-to-user contact)
- [ ] Case status timeline: Reported → Evidence collected → Under review → Decision → Resolved
- [ ] Case reference number and estimated resolution time shown
- [ ] Resolution notification: push + email with outcome and refund details

## PHASE 2 ADDITIONS — Growth (Month 6–18)

### 🆕 In-Platform Wallet (N1 — Phase 2)
Wallet reduces payment friction for repeat drivers and creates a float revenue stream. Needed before loyalty programme launches (rewards points redeem to wallet).

- [ ] Wallet balance displayed on home screen and booking confirmation
- [ ] Top up via card, Apple Pay, Google Pay (min £5 / max £500)
- [ ] Auto top-up: configurable threshold and top-up amount
- [ ] Use wallet balance to pay for bookings (priority over saved card)
- [ ] Split payment: wallet + card shortfall
- [ ] Wallet transaction history
- [ ] Refunds credited to wallet by default; optional card refund
- [ ] Stripe Customer Balance integration (float held by Zipgrid)
- [ ] FCA/HMRC legal review of wallet pre-payment model

### 🆕 Rewards & Loyalty Programme (N2 — Phase 2)
Rewards are a retention driver. Needed once the core booking loop is stable and drivers have had enough sessions to earn meaningful points.

- [ ] Points earning engine: session kWh, referrals, reviews, hosting, first booking welcome bonus
- [ ] Points redemption → Wallet credit (100 pts = £0.10)
- [ ] Tier system: Standard / Silver / Gold / Platinum (rolling 12-month points)
- [ ] Per-tier multipliers and privileges
- [ ] Progress bar toward next tier on profile screen
- [ ] CO₂ avoided badges and kWh milestone badges
- [ ] Streak rewards (4 consecutive charging weeks)
- [ ] Admin: configure earn rates, run bonus events, view points liability
- [ ] Points expiry (12 months of account inactivity)

### 🆕 Multi-Stop Trip Planner (N4 — Phase 2)
Trip planning requires Mapbox Directions API + range/weather AI logic. Depends on weather integration and CarPlay (Phase 2).

- [ ] Destination input (text or voice)
- [ ] Route calculated via Mapbox Directions API
- [ ] AI calculates charging stops: range × battery % × weather penalty
- [ ] Corridor charging stop search (ST_DWithin on route linestring)
- [ ] Trip plan displayed: depart → [stop 1] → [stop 2] → arrive
- [ ] Book all stops in one action (batch booking with payment holds)
- [ ] "My Trips" saved plans with live progress tracking
- [ ] Swap any stop with alternatives
- [ ] AI concierge: restaurant/café suggestions at each stop (Google Places API)
- [ ] Proactive re-route if a booked stop goes offline

### 🆕 AI Trip Concierge — Full (N5 — Phase 2)
Extends the agentic AI layer to full journey orchestration. Voice entry point: "Plan my trip to Manchester tomorrow and reserve all charging stops."

- [ ] Multi-turn conversation memory: "Use the same route as last time"
- [ ] Calendar integration: reads departure time from calendar event
- [ ] Proactive suggestions: "You have a meeting in Leeds at 9am — shall I plan charging for tomorrow night?"
- [ ] Real-time ETA adjustment: extends booking window if driver is running late
- [ ] Trip sharing: send trip plan to passenger via link

### 🆕 Weather & Range Intelligence (N7 — Phase 2)
Temperature-adjusted range prevents drivers from being stranded in winter.

- [ ] Met Office API or Open-Meteo integration for route weather forecast
- [ ] Per-vehicle range penalty table by temperature bracket
- [ ] Weather-adjusted range displayed on trip plan and map search
- [ ] Mid-trip weather change alert: "Heavy rain forecast — adding precautionary stop"
- [ ] Range penalty displayed on emergency charging mode screen

### 🆕 CarPlay & Android Auto (N6 — Phase 2)
In-car integration is Phase 2 because it requires platform stability first. Drivers need trust in the booking flow before handing it to the car screen.

- [ ] Apple CarPlay: CPMapTemplate with charging stop waypoints
- [ ] CarPlay: live session status (kWh, cost, ETA completion)
- [ ] CarPlay: voice commands via Siri integration
- [ ] Android Auto: equivalent map + session screen
- [ ] Android Auto: voice commands via Google Assistant
- [ ] Both: navigate to charging stop hands-off to Apple Maps / Google Maps

### 🆕 Insurance Hub — Full UI (N9 — Phase 2)
- [ ] Driver Insurance Hub: what's covered, what's not, how to claim
- [ ] Host Insurance Hub: Host Protection Guarantee summary, coverage active indicator, claim history
- [ ] Active claim tracker with case timeline
- [ ] Downloadable insurer disclosure template letter (host)
- [ ] Insurance Hub accessible from profile menu and post-incident flow

### 🆕 ESG Reporting — Core (N11 — Phase 2)
Corporate fleet customers will not sign up without ESG reporting. Needed for fleet tier launch.

- [ ] Per-session CO₂ avoided calculation (gCO₂/km × ICE equivalent)
- [ ] Cumulative CO₂ avoided on driver profile (lifetime total)
- [ ] Annual carbon summary: shareable / downloadable PDF certificate
- [ ] Fleet ESG dashboard: total kWh, CO₂ avoided, CO₂ per vehicle/driver
- [ ] Exportable ESG PDF report (board/investor/regulatory format)
- [ ] "Green charged" flag for sessions where host is on renewable tariff

### 🆕 AI Host Advisor — Expanded (N13 — Phase 2)
Expands beyond fault detection and pricing to full hosting intelligence.

- [ ] Demand forecasting: "Next week your listing is likely to be fully booked — consider raising prices"
- [ ] Listing coach: "Adding 2 more photos increases booking rate by 40% for listings like yours"
- [ ] Competitor insights: "3 nearby listings dropped prices this week — here's how you compare"
- [ ] Predictive maintenance: charger health score trend + "service recommended in 3 months"
- [ ] Review response drafting: AI writes a host reply suggestion for negative reviews

### 🆕 Fleet — Full Spec (N14 — Phase 2)
Full fleet tier defined in PRD Module. Roadmap items:

- [ ] Corporate account creation + Companies House verification
- [ ] Driver sub-accounts with individual logins
- [ ] Vehicle-to-driver assignment
- [ ] Spend policy controls (max per session, max per month, approved location types)
- [ ] Fleet analytics dashboard (cost per driver, per vehicle, efficiency score)
- [ ] Consolidated monthly invoice
- [ ] Xero / QuickBooks CSV export
- [ ] ESG dashboard (feeds into ESG module above)
- [ ] Auto-booking for recurring fleet charging slots

### 🆕 Employee Charging (N15 — Phase 2)
- [ ] Business host white-lists a corporate account for free charging
- [ ] Employees of white-listed company charge for free (host absorbs energy cost)
- [ ] Business host sees employee session costs in analytics as a separate line item
- [ ] Configurable cap: "Free up to 20 kWh per employee per month"
- [ ] HMRC benefit-in-kind guidance link in host portal (employer + employee awareness)
