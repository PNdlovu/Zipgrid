## 1. Design Philosophy

Zipgrid is a utility product used in real-world, often hands-free situations — in a car, in a driveway, in a café car park. The design must work when attention is split, lighting is variable, and the fastest path to the result is what matters.

Four principles drive every design decision:

| Principle | What it means in practice |
|-----------|--------------------------|
| **Voice-first, touch-second** | Every critical action must be completable without touching the screen. Touch is an equally valid fallback, never the only path. |
| **Zero ambiguity** | Status, cost, and action are always explicit. Users never have to guess what is happening or what it will cost. |
| **Speed over elegance** | Common flows are optimised for fewest taps/words. Rare flows can afford more steps. |
| **Trust through transparency** | Pricing breakdowns, commission rates, insurance status — always visible, never buried. |

## 3. Typography

**Typeface:** Inter (variable font — covers all weights from 100–900)  
**Fallback stack:** `-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`

### Type Scale

| Name | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| `display-xl` | 48px / 3rem | 700 | 1.1 | Hero headlines (web only) |
| `display-lg` | 36px / 2.25rem | 700 | 1.15 | Page titles |
| `display-md` | 28px / 1.75rem | 600 | 1.2 | Section headings |
| `heading-lg` | 22px / 1.375rem | 600 | 1.3 | Card headings, modal titles |
| `heading-md` | 18px / 1.125rem | 600 | 1.4 | Sub-headings |
| `heading-sm` | 16px / 1rem | 600 | 1.4 | List headings, form labels |
| `body-lg` | 16px / 1rem | 400 | 1.6 | Primary body copy |
| `body-md` | 14px / 0.875rem | 400 | 1.6 | Secondary body, descriptions |
| `body-sm` | 13px / 0.8125rem | 400 | 1.5 | Fine print, metadata |
| `label-lg` | 14px / 0.875rem | 500 | 1.4 | Form labels, tags |
| `label-md` | 12px / 0.75rem | 500 | 1.4 | Small labels, badges |
| `mono` | 13px / 0.8125rem | 400 | 1.5 | kWh values, cost figures, codes |

> **Rule:** All monetary values and kWh figures use `mono` — this prevents layout shift as numbers update in real-time.

### Number Display (Live Session)

Large live figures (kWh counter, £ cost meter) use a dedicated display style:
- **Font:** Inter, weight 700
- **Size:** 48–64px depending on screen size
- **Colour:** `--text-primary`
- **Sub-label:** `label-md`, `--text-secondary`

## 4. Spacing & Layout

**Base unit:** 4px  
**Scale:** 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80 · 96

### Layout Grid

| Breakpoint | Columns | Gutter | Margin | Max Content Width |
|------------|---------|--------|--------|-------------------|
| Mobile (< 640px) | 4 | 16px | 16px | 100% |
| Tablet (640–1024px) | 8 | 24px | 32px | 100% |
| Desktop (> 1024px) | 12 | 32px | 48px | 1280px |
| Wide (> 1440px) | 12 | 32px | auto | 1280px |

### Card Anatomy
```
┌─────────────────────────────────────────────────────┐
│  padding: 16px (mobile) / 20px (tablet+)            │
│                                                     │
│  [Cover image — 16:9 or 4:3]                        │
│  ─────────────────────────────────────────────────  │
│  [Heading]           spacing: 12px below image      │
│  [Subtext]           spacing: 4px below heading     │
│  [Stats row]         spacing: 12px below subtext    │
│                                                     │
│  border-radius: 12px                               │
│  border: 1px solid --border                        │
│  box-shadow: none (light) / none (dark)             │
└─────────────────────────────────────────────────────┘
```

> **No drop shadows.** Elevation is expressed through borders and background contrast, not shadows. Shadows feel heavy and dated.

## 5. Component Library

All components are built on **shadcn/ui** primitives with Zipgrid design tokens applied. shadcn/ui is copy-paste — components live in `components/ui/` and are fully customisable.

### 5.1 Buttons

| Variant | Use | Light | Dark |
|---------|-----|-------|------|
| `primary` | Main CTA (Book Now, Start Charging) | bg: `--accent`, text: white | same |
| `secondary` | Secondary action (View Details, Save) | bg: `--bg-secondary`, text: `--text-primary`, border: `--border` | bg: `--bg-secondary` |
| `destructive` | Delete, Cancel booking | bg: `--destructive`, text: white | same |
| `ghost` | Tertiary / navigation actions | bg: transparent, text: `--text-primary` | same |
| `outline` | Equal-weight alternatives | bg: transparent, border: `--border` | same |

**Button sizes:**

| Size | Height | Padding (x) | Font |
|------|--------|-------------|------|
| `sm` | 32px | 12px | `label-md` |
| `md` | 40px | 16px | `label-lg` |
| `lg` | 48px | 20px | `body-lg` 500 |
| `xl` | 56px | 24px | `heading-sm` |

> CTAs for primary booking actions (`Book Now`, `Start Charging`, `Stop Charging`) always use `lg` or `xl` — large enough to tap accurately in a car or outdoors.

### 5.2 Inputs & Forms

```
Label (label-lg, --text-primary)
  ↓
Input field
  • border: 1px solid --border
  • border-radius: 8px
  • padding: 10px 14px
  • height: 44px (minimum — WCAG touch target)
  • focus: border-color: --border-focus, ring: 2px --border-focus / 20%
  • error: border-color: --destructive
  ↓
Helper / error text (body-sm, --text-secondary / --destructive)
```

**Voice input variant:** Displays a microphone icon on the right edge. Tapping it activates the voice input overlay. When listening, the border pulses green (`--accent`).

### 5.4 Session Status Card

The active session card is the most critical UI component — it is visible for the entire duration of a charging session (30 mins – 8 hrs). It must be glanceable at a distance.

```
┌──────────────────────────────────────────────┐
│  ⚡ CHARGING                  [Stop button]  │  ← status badge + action
│                                              │
│     23.4 kWh          £7.49                 │  ← large mono numbers
│   DELIVERED           COST SO FAR           │
│                                              │
│  ████████████████████░░░░░░  67%            │  ← progress bar
│  Est. complete: 45 min                       │
│                                              │
│  [────────────────────── chart ─────────────]│  ← sparkline kWh over time
│                                              │
│  EO Charging · 11.2 kW · Sarah's Driveway   │  ← charger details
└──────────────────────────────────────────────┘
```

**Design rules for session card:**
- kWh and £ figures update in place without layout shift (monospace font, fixed-width container)
- The stop button is always visible — never below the fold
- Progress bar uses `--accent` fill on `--bg-tertiary` track
- Card background: `--bg-secondary` (slight contrast from page background)

## 7. Motion & Animation

**Philosophy:** Motion communicates state change — never decoration.

| Animation | Duration | Easing | Usage |
|-----------|----------|--------|-------|
| Page transition | 200ms | `ease-out` | Route changes |
| Bottom sheet open | 300ms | `spring(1, 80, 20)` | Map listing card, voice overlay |
| Bottom sheet close | 200ms | `ease-in` | |
| Toast slide in | 250ms | `ease-out` | Notifications |
| kWh number tick | 600ms | `ease-in-out` | Live session counter update |
| Waveform pulse | Loop 1000ms | `ease-in-out` | Voice listening state |
| Progress bar fill | 400ms | `ease-out` | Session progress update |
| Status badge pulse | Loop 2000ms | `ease-in-out` | Active charging indicator |
| Map pin bounce | 300ms | `spring` | New listing added to map |
| Accent button press | 100ms scale(0.97) | `ease-in` | Touch feedback |

> **Reduce motion:** All animations respect `prefers-reduced-motion`. When set, transitions are instant (0ms) or replaced with simple opacity fades.

## 8. Accessibility Standards

Target: **WCAG 2.1 AA** on all surfaces. WCAG 2.1 AAA on critical flows (booking, session, payments).

### Colour Contrast

| Context | Minimum ratio | Target |
|---------|--------------|--------|
| Body text on white | 4.5:1 | 7:1 (AA+) |
| Large text (18px+ bold) on white | 3:1 | 4.5:1 |
| `--text-primary` (#0A0A0A) on `--bg-primary` (#FFFFFF) | 20.5:1 ✅ | |
| `--accent` (#00C853) on white — text | ❌ fails (2.7:1) | **Never use accent as text on white** |
| `--accent` on `--accent-subtle` — icons only | 3.2:1 | Use for icons, not text |
| Dark mode `--text-primary` (#FAFAFA) on black | 19.6:1 ✅ | |

### Touch Targets
- Minimum: **44×44px** (WCAG 2.5.5 AAA)
- Primary CTAs: **48px height minimum**
- Map pins: **44×44px tap area** (visual pin can be smaller with padding)

### Screen Reader Support
- All interactive elements have descriptive `aria-label`
- Live session counter: `aria-live="polite"` — announced every 60 seconds, not every update
- Voice input button: `aria-label="Start voice command"`, `aria-pressed` reflects listening state
- Map: `role="application"` with keyboard navigation for listing cards
- Icons without adjacent text: `aria-hidden="true"` + sibling visually hidden text

### Keyboard Navigation
- Full keyboard nav through all flows (Tab order matches visual order)
- Focus visible ring: 2px `--border-focus` offset 2px
- Escape closes all modals, bottom sheets, voice overlay
- Session stop button: focusable, space/enter activates

## 9. Voice UX Guidelines

### Voice Affordance
- Persistent microphone icon in bottom navigation bar (always visible)
- Subtle pulsing animation on mic icon when a voice action is available for the current screen
- Never autoplay audio — user always initiates voice interaction

### Response Design
- Platform voice responses: **short, direct, confirmation-first**
  - ✅ "Booked. Sarah's driveway, Thursday 10am. Check-in code ZG-8472."
  - ❌ "Great news! I've successfully processed your booking request for Sarah's charger located at..."
- Error responses acknowledge clearly and offer the next step
  - "That charger isn't available Thursday. The next available slot is Friday at 9am — shall I book that?"
- Monetary amounts always spoken as "7 pounds 49" not "seven point four nine"
- kWh spoken as "23.4 kilowatt hours" not "twenty three point four"

### Disambiguation
When intent is unclear, ask **one specific question** — not a menu:
- ✅ "Did you mean your usual Thursday morning slot at Sarah's?"
- ❌ "Would you like to: (1) Book a charger (2) Check session status (3) View earnings?"

## 10. Screen-by-Screen UX Notes

### 10.1 Map Search Screen (Driver)
- Default view: user location centred, 2km radius, all active listings as pins
- Bottom sheet (collapsed): search bar + filter chips
- Filter chips visible without opening full filter panel: Plug Type · Level 2 · Price · Available Now
- Listing card slides up from bottom on pin tap (50% screen height)
- Full listing detail on card swipe up or "View Details" tap
- Voice mic persistent in header

### 10.2 Booking Flow
- 3 steps maximum: (1) Date/time → (2) Confirm cost → (3) Payment
- Step 3 is payment confirmation only — never re-show all details
- Estimated cost shown in large type before payment — never hidden until after
- After payment: full-screen confirmation with QR code as the primary element

### 10.3 Active Session Screen
- This screen should auto-open when a session starts (push notification deep link)
- No navigation away from this screen during active session without confirmation
- "Stop Charging" requires a 2-tap confirm: tap once → confirm button appears, tap again → stop sent
  - Prevents accidental session termination (costs host revenue, inconveniences driver)

### 10.4 Host Earnings Dashboard
- Primary KPI displayed above the fold: this month's earnings (large, green)
- Chart: last 30 days bar chart — one bar per day
- Below chart: listing performance table (booking count, kWh, revenue per listing)
- Payout status always visible: "Next payout: £94.20 — arrives Monday"

### 10.5 Onboarding — Voice-Guided
- Each step has a spoken prompt that plays once on load (user can re-play)
- Progress indicator: 5 dots at top, filled as steps complete
- Tapping anywhere on the screen while voice is playing pauses it
- Estimated time shown: "About 4 minutes to set up"

## 12. Do / Don't Summary

| ✅ Do | ❌ Don't |
|-------|---------|
| White backgrounds, true black dark mode | Dark blue, grey, or "charcoal" dark mode |
| `--accent` green for charging status and CTAs | Use accent as body text colour |
| Borders to define surfaces | Drop shadows |
| Monospace for live numbers | Variable-width fonts on counters |
| Large touch targets (44px+) on all interactive elements | Tiny icons or text links as the only tap target |
| Short, direct voice responses | Long-form voice narration |
| 2-tap confirm on destructive session actions | Single tap to stop an active session |
| Show cost before every payment step | Surprise charges post-payment |
| `prefers-reduced-motion` respected | Autoplay animations regardless of system setting |
