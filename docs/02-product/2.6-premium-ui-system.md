## 1. The Premium Standard

There is no excuse for a cheap-looking product in 2027. Users judge trust by appearance — and Zipgrid handles money, property access, and safety. The UI must inspire confidence.

**The standard:**
- Clean, not sparse
- Premium, not corporate-cold
- Modern, not trendy
- Functional, not flashy
- Consistent, not varied

**What premium means in practice:**
```
✅ One clean typeface (Inter)
✅ One accent colour (#00C853)
✅ Borders to define surfaces — never drop shadows
✅ Generous white space
✅ Sharp corners on interactive elements (not pill buttons)
✅ Monospace font for numbers (kWh, £, codes)
✅ Icons that look like they were drawn by a human for this product
✅ Every state accounted for: loading, empty, error, success, offline

❌ Gradient backgrounds
❌ Glassmorphism / frosted glass
❌ "AI-generated" icon packs
❌ Overuse of rounded corners ("squircles everywhere" look)
❌ Inconsistent spacing
❌ Card overload — everything in a card
❌ Dark blue or charcoal "dark mode"
❌ Neon accent colours
❌ Drop shadows on everything
❌ Animations that serve no purpose
```

## 2. Three-Mode Colour System

Documented fully in `2.4-ux-design-guidelines.md`. Summary:

| Mode | Background | Text | Use |
|------|-----------|------|-----|
| **Light** | `#FFFFFF` | `#0A0A0A` | Default, daytime |
| **Dark** | `#000000` TRUE BLACK | `#FAFAFA` | Night, OLED, drivers in cars |
| **Night** | `#0D0D0D` | `#F5E6C8` warm | Extended desk use, fleet managers |

**The critical rule:** Dark mode is `#000000`. Not `#111111`. Not `#1A1A1A`. Not dark blue. Pure black. This is a product decision, not a technical shortcut.

## 3. Iconography System

### The Rule: Custom Icons Only

No icon packs. No Heroicons used as-is. No AI-generated icon sets. No Material Icons with default styling.

Zipgrid uses **Lucide Icons** as the base but with strict customisation:
- Stroke width: exactly 1.5px on all sizes
- Corner radius: consistent across all icons
- Padding: equal on all sides
- Custom icons are drawn for domain-specific concepts that Lucide doesn't have

### Icon Categories Required

```
CHARGING DOMAIN
  ⚡  Lightning bolt (filled) — active charging, brand mark
  🔌  Charger plug — listing type indicator
  📊  Power meter — kWh/kW display
  🔋  Battery — vehicle state of charge

NAVIGATION
  🗺️  Map pin (custom — rounded bottom, clean) — charger location
  📍  Current location dot — driver position
  🗺️  Route line — trip planner

PAYMENTS
  💳  Card — payment method
  👛  Wallet — Zipgrid wallet balance
  ↑   Payout arrow — host earnings
  ★   Star coin — rewards points

TRUST & SAFETY
  🛡️  Shield — safety score, insurance
  ✓   Tick badge — verified status
  ⚠️   Warning triangle — fault, safety issue
  ✓   Superhost crown — superhost badge

MARKETPLACE
  🔧  Wrench — installer services
  📦  Box — hardware products
  ⭐  Star — ratings/reviews

VOICE & AI
  🎙️  Microphone — voice input
  ✦   Sparkle (minimal) — AI suggestion (NOT the generic AI star)
  💬  Chat bubble — support

STATUS
  ●   Circle filled — online/active
  ◯   Circle outline — offline/inactive
  ⊘   Strikethrough circle — blocked/unavailable
```

### Icon Do / Don't

```
✅ DO:
  - Use consistent 24px size in navigation and lists
  - Use 20px in dense content areas
  - Use 32px for prominent feature icons
  - Add aria-hidden="true" to all decorative icons
  - Always pair icons with text labels in navigation

❌ DON'T:
  - Use different icon styles on the same screen
  - Use filled and outline variants of the same icon interchangeably
  - Use icons without labels in mobile navigation
  - Use AI-generated icons (they look inconsistent close up)
  - Use emoji as UI icons
  - Use icon fonts (SVG sprites only)
```

## 4. Button System

### Button Rules (Non-Negotiable)

```
1. No pill buttons (border-radius: 6px on all buttons — not 9999px)
2. Primary button: accent green background, white text, sharp corners
3. Secondary button: transparent background, border, no fill
4. Destructive button: red background, white text
5. Every button shows loading state when action is in progress
6. Disabled state is visually distinct (not just greyed slightly)
7. Touch target: minimum 44px height on ALL buttons
8. Icon buttons: 44×44px minimum with tooltip
```

### Button States (All Must Be Designed)

```typescript
// Every button must handle all 5 states:
type ButtonState = 'default' | 'hover' | 'active' | 'disabled' | 'loading'

// Loading state example — correct implementation:
<Button
  onClick={handleBookNow}
  disabled={isBooking}
  aria-busy={isBooking}
  className="min-h-[44px]"
>
  {isBooking ? (
    <>
      <Spinner className="mr-2 h-4 w-4 animate-spin" aria-hidden />
      <span>Booking...</span>
    </>
  ) : (
    'Book Now'
  )}
</Button>
```

### Button Hierarchy

```
Screen should have at most:
  1×  Primary (the main action — "Book Now", "Start Charging")
  1×  Secondary (the alternative — "Save for later", "View details")
  N×  Ghost (tertiary actions — "Cancel", "Back", "Help")

If you have two primary buttons on one screen, one of them is wrong.
```

## 5. Offline Mode

### Offline-First Principles

EV drivers lose signal in underground parking, rural areas, garages, and tunnels. The app must be **fully usable** for core flows when offline.

### What Must Work Offline

| Feature | Offline Behaviour |
|---------|-----------------|
| Map | Shows cached listings (last 15-minute cache) |
| Booking detail | Shows fully from cache — QR code, PIN, access instructions |
| Active session screen | Shows last-known kWh/cost; "Updates paused" banner |
| Host earnings dashboard | Shows last-fetched data; "Showing cached data from X" label |
| Knowledge base / FAQ | Fully cached after first load |
| Voice commands | Reads from cache; no booking actions until online |
| My bookings list | Fully cached |

### What Cannot Work Offline (Graceful Error)

| Feature | Offline Message |
|---------|---------------|
| New booking | "You're offline — connect to book a new session" |
| Start session | "You're offline — connect to start charging" |
| Payment | "You're offline — connect to complete payment" |
| Live session kWh | Banner: "Live updates paused — last reading: [X] kWh" |

### Offline Banner Component

```typescript
/**
 * @file OfflineBanner.tsx
 * @description Persistent banner shown when user is offline.
 * Non-intrusive — sits at top of screen, doesn't block content.
 * Disappears automatically when connection restores.
 */
'use client'

import { useOnlineStatus } from '@/hooks/useOnlineStatus'

export function OfflineBanner() {
  const isOnline = useOnlineStatus()
  if (isOnline) return null

  return (
    <div
      role="status"
      aria-live="polite"
      data-testid="offline-banner"
      className="sticky top-0 z-50 w-full bg-warning/10 border-b border-warning px-4 py-2 text-sm text-warning-foreground text-center"
    >
      You&apos;re offline — showing cached data
    </div>
  )
}
```

### Service Worker Strategy (Next.js)

```typescript
// next.config.ts — register service worker for offline caching
// Using next-pwa or custom service worker

const CACHE_STRATEGIES = {
  // Cache-first: static assets, icons, fonts
  static: { strategy: 'CacheFirst', maxAge: 7 * 24 * 60 * 60 },

  // Network-first with cache fallback: API responses
  api: { strategy: 'NetworkFirst', maxAge: 15 * 60 },

  // Cache-first with background revalidation: map tiles
  tiles: { strategy: 'StaleWhileRevalidate', maxAge: 60 * 60 },
}

// Pre-cache on install:
const PRE_CACHE_URLS = [
  '/map',
  '/bookings',
  '/profile',
  '/host/dashboard',
]
```

## 6. Error Boundary System

### The Rule: Every Screen Has a Boundary

No screen should ever show a blank white page or a React error stack trace to a user. Every module has an error boundary.

```typescript
/**
 * @file ErrorBoundary.tsx
 * @description Global error boundary — catches all uncaught React errors.
 * Shows a friendly fallback. Logs to Sentry. Provides Retry + Report.
 * Wrap every major route segment with this.
 */

export class ErrorBoundary extends React.Component<
  { children: React.ReactNode; fallback?: React.ReactNode },
  { hasError: boolean; errorId: string }
> {
  state = { hasError: false, errorId: '' }

  static getDerivedStateFromError() {
    return { hasError: true, errorId: crypto.randomUUID() }
  }

  componentDidCatch(error: Error, info: React.ErrorInfo) {
    // Send to Sentry with full context — never show raw error to user
    Sentry.captureException(error, {
      extra: { componentStack: info.componentStack, errorId: this.state.errorId }
    })
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback ?? (
        <ErrorFallback
          errorId={this.state.errorId}
          onRetry={() => this.setState({ hasError: false })}
        />
      )
    }
    return this.props.children
  }
}
```

### Error Boundary Levels

```
App-level boundary:         Catches catastrophic failures
  └── Route-level boundary: Catches page-level failures
        └── Feature-level boundary: Catches component failures (map, session, voice)
              └── API error handling: Catches data fetch failures
```

### Error Categories and Fallbacks

| Error Type | Fallback UI | Action |
|------------|------------|--------|
| Network error | "Connection problem — please check your internet" + Retry button | Log to Sentry |
| Charger offline | "This charger is temporarily unavailable" + Show nearest alternative | Alert ops |
| Payment failed | "Payment couldn't be processed" + Try different card + Support link | Log to Sentry |
| Session stuck | "Your session may have an issue" + Contact support CTA | Alert ops + auto-diagnose |
| AI agent error | Fall back to text response: "I couldn't process that — try typing instead" | Log to Sentry |
| Voice recognition failed | Show text input fallback automatically | Log to PostHog |
| Map failed to load | Show list view of nearby listings | Log to Sentry |
| Offline + no cache | "No cached data available — connect to load" | Log to PostHog |

## 7. Landing Pages — Premium Standards

### Navigation: No Guesswork

Every page of the landing site must answer these three questions in under 3 seconds:
1. What is this? (What does Zipgrid do?)
2. Who is it for? (Drivers? Homeowners? Businesses?)
3. What do I do next? (One clear CTA)

### Navigation Structure

```
zipgrid.co.uk/
├── Home
├── For Drivers            → How to find and book charging
├── For Homeowners         → How to earn from your charger
├── For Businesses         → SMB dashboard and analytics
├── For Installers         → Marketplace and jobs
├── Pricing                → All subscription tiers, comparison vs. competitors
├── Safety & Insurance     → Trust signals, damage recovery, own-cover guidance
├── Help Centre            → Knowledge base + AI assistant
└── Blog                   → EV guides, earnings stories, product news
```

### Landing Page Layout Rules

```
Header:
  - Logo left
  - Navigation centre (desktop) / hamburger (mobile)
  - Primary CTA right ("Get started free" or "List your charger")
  - Minimal — no mega menus

Hero section:
  - Headline: 2–4 words maximum
  - Subheadline: one sentence
  - ONE primary CTA button
  - ONE secondary link ("See how it works")
  - Hero image or illustration: premium, contextual (NOT stock photography)

Feature sections:
  - Maximum 3 features per section
  - Icon + heading + 1-sentence description
  - Alternate image/text placement (not all text-left)

Social proof:
  - Real host earnings (anonymised but specific: "£140/month")
  - Real session counts
  - Real star ratings

CTA sections:
  - Repeated 2–3 times down the page
  - Different copy each time (not copy-paste)
  - Always segment-aware: "Start earning" vs "Find charging"

Footer:
  - Clean, minimal
  - Links: Privacy, Terms, Security, Accessibility Statement
  - Social links
  - ICO registration number
  - Company registration number
```

### Typography on Landing Pages

```
Headline:     Inter 700, 48–64px, tight line-height (1.1)
Subheadline:  Inter 400, 20–24px, comfortable line-height (1.5)
Body:         Inter 400, 16px, generous line-height (1.6)
CTA button:   Inter 600, 16px, uppercase tracking (0.02em)

Colour rules on landing:
  - Text: #0A0A0A on white — never mid-grey on white (fails contrast)
  - Accent: #00C853 on CTAs only — not as text, not as section backgrounds
  - Sections: White alternating with #F7F7F7 (very subtle separation)
  - No coloured section backgrounds — grey scale only
```

## 8. Empty States

Every list, map, and dashboard must have a designed empty state — not a blank screen.

```typescript
/**
 * @file EmptyState.tsx
 * @description Empty state component for all list/map/dashboard views.
 * Always includes: icon + heading + subtext + action.
 */

type EmptyStateProps = {
  icon: LucideIcon
  heading: string
  description: string
  action?: { label: string; onClick: () => void }
}

// Examples:
// Map search with no results:
//   icon: MapPin
//   heading: "No chargers found here"
//   description: "Try expanding your search radius or adjusting your filters"

// Host with no bookings:
//   icon: Calendar
//   heading: "No bookings yet"
//   description: "Your listing is live — your first booking could arrive any time"

//   icon: Zap
//   heading: "Your charging history is empty"
//   description: "Book your first session to see it here"
//   action: { label: "Find a charger", onClick: goToMap }
```

## 9. Loading States

Skeletons over spinners. Spinners only for button actions.

```
Page loading:    Skeleton (same shape as actual content — no layout shift on load)
Button action:   Spinner inside button + "Loading..." text
Data refresh:    Subtle pulse on data values (not full skeleton — content is there)
Map loading:     Skeleton pins while PostGIS query runs
Session data:    Pulse animation on kWh/cost counter while awaiting first update
```

## 10. Accessibility Quick Reference

| Requirement | Implementation |
|-------------|---------------|
| Colour contrast | AA minimum (4.5:1 for text); tested with axe in every E2E test |
| Touch targets | 44×44px minimum on ALL interactive elements |
| Focus ring | 2px solid `--ring` colour, 2px offset — always visible |
| Screen reader | `aria-label` on all icon-only buttons; `aria-live` on session counters |
| Skip navigation | First focusable element on every page |
| Form labels | Every `<input>` has an associated `<label>` — no placeholder-only labels |
| Error messages | Linked to field with `aria-describedby`; describe the problem and the fix |
| Images | Alt text on all meaningful images; `aria-hidden` on decorative ones |
| Motion | All animations respect `prefers-reduced-motion: reduce` |
| Language | `lang="en-GB"` on all pages; updated per locale |
