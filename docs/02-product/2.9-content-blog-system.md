## 1. Content Philosophy

Zipgrid's content engine has one job: **make EV charging less confusing**.

The EV world is full of jargon — OCPP, kWh, CCS2, SMETS2, Agile tariffs, V2G, PAS 1899. None of this should appear in user-facing content without an immediate plain-English explanation.

**The content brand voice:**
- Helpful friend, not technical manual
- Short sentences
- Active voice always
- One idea per paragraph
- Outcome-first (what it means for the user, not how it works)

**Example:**
```
❌ WRONG (technical):
"Smart charging using OCPP 1.6J allows the Central System to send
SetChargingProfile messages to configure time-of-use load management
based on half-hourly DNO tariff data."

✅ CORRECT (human):
"Smart charging means your car charges itself when electricity
is cheapest — usually overnight. You save money without thinking about it."
```

## 3. CMS Specification

### Platform: Contentlayer + MDX (built into Next.js monorepo)

Content lives in the monorepo at `apps/web/content/blog/` as `.mdx` files. This gives:
- Full TypeScript type safety on frontmatter
- No external CMS cost
- Git-based version control for all content
- Easy handoff to developers or writers
- ISR rendering (content updates without redeploy)

For a non-technical content editor: use **Outstatic** (open-source Git-based CMS that provides a web UI over the MDX files) or migrate to **Sanity** (Phase 2) when content volume warrants it.

### Article Frontmatter Schema

```typescript
/**
 * @file content/blog/[slug].mdx
 * @description Article frontmatter schema — all fields required.
 */
type ArticleFrontmatter = {
  title:          string          // Plain English. Max 60 chars for SEO.
  slug:           string          // URL: /blog/earn-from-home-charger
  description:    string          // 120–155 chars for SEO meta description
  publishedAt:    string          // ISO date: '2027-01-15'
  updatedAt:      string          // ISO date — shown to readers
  category:       BlogCategory    // One of the 7 categories above
  author:         string          // 'Zipgrid Team' or named author
  readTimeMinutes: number         // Auto-calculated from word count
  featuredImage:  string          // CDN URL — required for social sharing
  featuredImageAlt: string        // Descriptive alt text
  tags:           string[]        // For related article grouping
  targetAudience: ('driver' | 'homeowner' | 'smb' | 'all')[]
  isFeatured:     boolean         // Show on homepage content section
  seoKeyword:     string          // Primary SEO keyword for this article
}
```

### URL Structure

```
zipgrid.co.uk/blog/                           — All articles
zipgrid.co.uk/blog/category/earn-from-charger — Category page
zipgrid.co.uk/blog/earn-money-home-ev-charger — Individual article
zipgrid.co.uk/guides/                         — How-to guides (separate from blog)
zipgrid.co.uk/guides/connect-eo-charger       — Setup guide
```

## 4. SEO Requirements

Every article must be written with one primary search keyword in mind.

### On-Page SEO Checklist (per article)

```
□ Title tag: primary keyword in first 60 characters
□ Meta description: 120–155 characters, includes keyword, ends with a benefit
□ H1: matches title tag (only one H1 per page)
□ H2s: use related/secondary keywords naturally
□ First 100 words: primary keyword appears once
□ Internal links: minimum 2 links to other Zipgrid pages
□ External links: 0–1 high-authority links (GOV.UK, Which?, Octopus)
□ Featured image: WebP format, descriptive alt text, < 100KB
□ Word count: minimum 600 words for blog, 800 for guides
□ Schema markup: Article schema on all blog posts
□ Canonical URL: self-referencing canonical tag
```

## 5. Convenience-First Language Guide

This guide applies to ALL user-facing text across the platform — not just the blog.

### Core Rule
**Every sentence answers: "What does this mean for me?"**

Not: "Session data is transmitted via OCPP MeterValues protocol"
But: "We track exactly how much you charged so you're only billed for what you use"

### Forbidden Words / Phrases (User-Facing)

```
❌ OCPP           → ✅ "smart charger connection"
❌ kWh            → ✅ "units of energy" or just state the number with context
❌ Firmware       → ✅ "charger software"
❌ Protocol       → Never mention
❌ API            → Never mention
❌ Backend        → Never mention
❌ Integration    → ✅ "connects with"
❌ Credentials    → ✅ "login details"
❌ Authentication → ✅ "sign in"
❌ As per         → ✅ "based on"
❌ Utilise        → ✅ "use"
❌ Leverage       → ✅ "use"
❌ Onboarding     → ✅ "getting started" or "setup"
❌ KPI            → Never in user-facing text
❌ LTV            → Never in user-facing text
❌ Connector      → ✅ "charging plug" or "charging port"
❌ EVSE           → ✅ "charger"
❌ PEV            → ✅ "electric car"
```

### Tone Calibration Examples

| Situation | Wrong | Right |
|-----------|-------|-------|
| Charging complete | "Session terminated. 23.1 kWh delivered." | "Charging done. You added about 90 miles of range." |
| Idle fee | "Idle fee of £0.10/min applied post-session" | "Your car finished charging 12 minutes ago. Small fees apply to keep the spot fair for everyone." |
| Fault detected | "OCPP StatusNotification: Faulted — GroundFailure" | "Your charger has a small issue. We'll help you sort it." |
| Low battery | "SoC below threshold — emergency mode available" | "Your battery is getting low. Shall we find you a charger?" |
| Earnings | "Net payout after 15% platform commission deduction" | "You earned £6.73. Zipgrid's small fee keeps the platform running." |
