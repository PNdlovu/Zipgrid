## 1. The Non-Negotiables

These are the ten rules that apply to every file, every PR, every day. No exceptions.

```
1.  No stubs. No mocks. No placeholders in production code.
2.  Every button has a working onClick handler.
3.  Every form has working validation and submission.
4.  Every API route is authenticated, validated, and error-handled.
5.  Every module is fully wired — no disconnected components.
6.  Every file has a JSDoc/TSDoc header comment.
7.  No duplicate code — extract shared logic into utilities.
8.  No hardcoded strings — all user-facing text in i18n files.
9.  No assumptions — if unsure, open a question before coding.
10. No half-cooked files — if a file ships, it works end-to-end.
```

## 2. Theme System

### 2.1 Three Modes

Zipgrid implements three visual modes. Every component must work correctly in all three.

| Mode | Class on `<html>` | Background | Foreground | Use Case |
|------|-------------------|-----------|-----------|---------|
| **Light** (default) | _(none)_ | `#FFFFFF` | `#0A0A0A` | Daytime, web default |
| **Dark** | `.dark` | `#000000` | `#FAFAFA` | Night driving, OLED phones, evening use |
| **Night** | `.night` | `#0D0D0D` | `#F5E6C8` (warm) | Extended desk use, fleet managers, eye strain |

**Dark mode is true black — not dark blue, not dark grey, not #111. Exactly #000000.**

Night mode shifts text toward warm amber to reduce blue light for long-session users. Background is near-black (#0D0D0D) with no blue channel.

## 8. Pagination

Every list endpoint is paginated. No endpoint returns unbounded results.

```typescript
/**
 * @file pagination.ts
 * @description Shared cursor-based and offset pagination utilities.
 * All list endpoints use one of these two strategies.
 *
 * Offset pagination: simple, predictable — use for admin lists, history
 * Cursor pagination: no duplicate items on refresh — use for infinite scroll maps
 */

// Offset pagination (standard)
export const PaginationSchema = z.object({
  page:     z.coerce.number().int().min(1).default(1),
  pageSize: z.coerce.number().int().min(1).max(100).default(20),
})

export type PaginationParams = z.infer<typeof PaginationSchema>

export function paginate(query: Query, { page, pageSize }: PaginationParams) {
  return query
    .limit(pageSize)
    .offset((page - 1) * pageSize)
}

// Standard paginated response envelope
export function paginatedResponse<T>(
  data: T[],
  total: number,
  { page, pageSize }: PaginationParams
) {
  return {
    success: true,
    data,
    meta: {
      page,
      pageSize,
      total,
      totalPages: Math.ceil(total / pageSize),
      hasNextPage: page * pageSize < total,
      hasPrevPage: page > 1,
    },
  }
}
```

UI components use `TanStack Query` with `useInfiniteQuery` for infinite scroll and `useQuery` for standard paginated tables.

## 9. AI Guards & Hallucination Prevention

The AI/voice layer has strict guardrails. This section defines them in code terms.

### 9.1 System Prompt Immutability

```python
            HumanMessagePromptTemplate.from_template("{input}"),  # User input — sandboxed
        ])
        | llm.bind_tools(ALLOWED_TOOLS)  # Only allowlisted tools
        | ToolCallValidator()             # Validate all tool parameters
        | AgentExecutor(...)
    )
```

### 9.2 Input Sanitisation

```python
MAX_VOICE_INPUT_CHARS = 500
MAX_QA_INPUT_CHARS = 1000

def sanitise_user_input(text: str, max_length: int) -> str:
    """
    @description Strip injection attempts and enforce length limit.
    Detects: prompt injection patterns, role override attempts,
    system prompt extraction attempts.
    """
    # Detect injection patterns
    injection_patterns = [
        r"ignore (previous|all|above) instructions",
        r"you are now",
        r"system prompt",
        r"act as",
        r"DAN mode",
        r"jailbreak",
    ]
    for pattern in injection_patterns:
        if re.search(pattern, text, re.IGNORECASE):
            raise ValueError("Input contains prohibited content")

    return text[:max_length].strip()
```

### 9.3 Tool Call Validation

```python
ALLOWED_TOOL_NAMES = {
    "search_listings",
    "create_booking",
    "get_session_status",
    "stop_session",
    "get_tariff_rates",
    "schedule_charging",
    "search_installers",
    "get_host_earnings",
    "query_knowledge_base",
    "detect_fault",
    "plan_trip",
    "get_user_preferences",
}

class ToolCallValidator:
    """
    @description Validates every AI tool call before execution.
    Prevents the AI from calling tools outside the allowlist.
    Validates that tool parameters match expected schemas.
    Enforces that user can only act on their own data.
    """
    def validate(self, tool_name: str, tool_input: dict, user_id: str) -> dict:
        if tool_name not in ALLOWED_TOOL_NAMES:
            raise PermissionError(f"Tool {tool_name} not permitted")

        # Enforce data ownership — AI cannot act on another user's data
        if "user_id" in tool_input and tool_input["user_id"] != user_id:
            raise PermissionError("Cannot act on another user's data")

        # Validate against tool-specific Pydantic schema
        schema = TOOL_SCHEMAS[tool_name]
        return schema(**tool_input).dict()
```

### 9.4 Confidence Thresholds

```typescript
/**
 * @file intent-router.ts
 * @description Routes parsed voice intent to appropriate action.
 * Low-confidence intents are NEVER auto-executed.
 * Below threshold → ask for clarification.
 */

const CONFIDENCE_THRESHOLDS = {
  auto_execute:    0.90,  // Execute immediately, no confirmation
  confirm_first:   0.75,  // Show what will happen, ask to confirm
  clarify:         0.60,  // Ask clarifying question
  reject:          0.00,  // Below 0.60 → "I didn't understand that"
} as const

export function routeIntent(intent: ParsedIntent): IntentAction {
  if (intent.confidence >= CONFIDENCE_THRESHOLDS.auto_execute) {
    // Only for read-only or reversible actions
    return { type: 'execute', requiresConfirmation: false }
  }
  if (intent.confidence >= CONFIDENCE_THRESHOLDS.confirm_first) {
    return { type: 'confirm', requiresConfirmation: true }
  }
  if (intent.confidence >= CONFIDENCE_THRESHOLDS.clarify) {
    return { type: 'clarify', question: generateClarifyingQuestion(intent) }
  }
  return { type: 'reject', message: "I didn't quite catch that. Could you try again?" }
}

// RULE: Irreversible actions (payments, bookings) ALWAYS require confirmation
// regardless of confidence score
export function requiresConfirmation(intent: ParsedIntent): boolean {
  const ALWAYS_CONFIRM = ['create_booking', 'cancel_booking', 'make_payment', 'redeem_rewards']
  return ALWAYS_CONFIRM.includes(intent.action) || intent.confidence < 0.90
}
```

## 10. Security-First Coding Patterns

```typescript
// ✅ ALWAYS use parameterised queries — NEVER string interpolation
// ❌ WRONG
const query = `SELECT * FROM users WHERE email = '${email}'`

// ✅ CORRECT (Drizzle ORM)

// ❌ WRONG
export async function POST(req: Request) {
```

```typescript
/**
 * @file instrumentation.ts (Next.js root)
 * @description OpenTelemetry instrumentation for distributed tracing.
 * Every request gets a traceId that spans all services.
 */

// Every log line MUST include:
// - timestamp (ISO 8601)
// - level (error | warn | info | debug)
// - service (api | ocpp | ai)
// - traceId (for cross-service correlation)
// - userId (where authenticated — never log passwords or tokens)
// - message

// ✅ CORRECT logging
logger.info({
  timestamp: new Date().toISOString(),
  level: 'info',
  service: 'api',
  traceId: req.headers.get('x-trace-id'),
  userId: user.id,
  action: 'booking.created',
  bookingId: booking.id,
  listingId: booking.listingId,
  message: 'Booking created successfully',

// ❌ WRONG — never log sensitive data
logger.info(`User ${user.email} with card ${cardNumber} paid ${amount}`)
```

## 13. React Native Mobile App Standards

The React Native app shares types, API client, and business logic with the Next.js web app via the monorepo `packages/` directory.

```
packages/
  api-client/      — Shared API client (TanStack Query + typed fetch)
  types/           — All shared TypeScript types
  utils/           — Shared utilities (formatters, validators, constants)
  ui-primitives/   — Shared design tokens (colours, spacing, typography)

apps/
  web/             — Next.js 15 web app
  mobile/          — React Native (Expo) mobile app
  ocpp-service/    — Node.js OCPP Central System
  ai-service/      — Python FastAPI AI/Voice service
```

**React Native rules:**
- No Expo Go — use Expo Dev Client for all development
- All navigation via Expo Router (file-based, mirrors Next.js App Router structure)
- Shared types from `@zipgrid/types` — never redefine in mobile
- API calls via `@zipgrid/api-client` — same hooks as web
- Platform-specific components in `.ios.tsx` / `.android.tsx` files where needed
- Haptic feedback on all primary CTAs (booking confirm, session stop)
- Background fetch for session monitoring (driver app stays live during charging)
