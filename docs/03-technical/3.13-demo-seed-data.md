## 1. The Anti-Replit Rule

The most common mistake in early-stage platform demos is building a "theatrical" application — an app that looks real but has hardcoded data, fake API responses, and buttons that do nothing. This creates two serious problems:

1. **Investor problem:** Sophisticated investors spot theatre immediately. When they ask "what happens if I click this?", the answer cannot be "that's not wired up yet."
2. **Developer problem:** Removing mock data from a codebase that was built around it takes longer than building it correctly the first time.

**The rule is simple:** If a screen exists in the app, it must show real data fetched from the real database. If data does not exist yet, the screen shows a well-designed empty state — never fake hardcoded content.

## 5. Demo OCPP Simulator

For demo environments where real charger hardware is not available, a lightweight OCPP simulator provides authentic session telemetry.

```javascript
/**
 * @file ocpp-simulator/demo-charger.js
 * @description Demo OCPP charger simulator.
 * Connects to the OCPP Central System and simulates a real session.
 * Used for developer demos and investor showcases.
 * Run: node demo-charger.js --chargePointId DEMO-CHARGER-001
 */

// Simulates: BootNotification → Authorize → StartTransaction
//            → MeterValues (every 30s) → StopTransaction
// Produces: realistic kWh readings, power curves, temperature data
// Session duration: configurable (default: 90 minutes compressed to 3 minutes for demo)
```

The simulator runs in compressed time: a 90-minute session plays out in 3 minutes for live demos, with realistic power curves (charges fast to 80%, then tapers) and real kWh calculations.

## 8. Seed Data Maintenance Rules

```
RULE 1: Never hardcode data in components.
  All demo data comes from the database, fetched by real API calls.
  If a screen shows data, that data is in the DB.

RULE 2: Demo database is separate from test database.
  DATABASE_URL_DEMO  → demo environment (seeded, persistent)
  DATABASE_URL_TEST  → test environment (reset per test run)
  DATABASE_URL       → production (never seeded with demo data)

RULE 3: Seed data is refreshable.
  npm run db:seed:demo  → resets and re-seeds the demo database
  This runs in < 30 seconds and restores everything to a clean demo state.

RULE 4: All seed UUIDs are fixed (not random).
  Fixed UUIDs enable reliable deep-links in investor demos
  e.g. /listings/40000000-0000-0000-0000-000000000001 always works

RULE 5: All seed financial figures are realistic but clearly demo.
  Earnings are in the believable range (not £0 or £10,000).
  Session costs have pence variation (£5.83 not £5.00 — realism matters).

RULE 6: No "lorem ipsum" anywhere.
  All text content is real, readable, and reflects the product voice.
  All photos are real (licensed stock or genuine product photos).
```
