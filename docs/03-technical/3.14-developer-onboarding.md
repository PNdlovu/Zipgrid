## 1. What We Are Building

Zipgrid is a two-sided marketplace:
- **Hosts** (homeowners + businesses) list their EV chargers
- **Drivers** book and pay for charging sessions
- **AI** automates scheduling, pricing, trip planning, and fault diagnosis
- **Voice** lets users control everything hands-free

The platform has four main services:
1. **Next.js web app** — all user-facing UX + API routes
2. **OCPP WebSocket service** — real-time communication with smart chargers
3. **AI/Voice service** — LangChain agents, RAG, voice intent parsing
4. **React Native mobile app** — iOS + Android (Expo)

**Golden rule:** If you are looking for a type, import from `@zipgrid/types`. If you need an API call, import from `@zipgrid/api-client`. Never define domain types inline in a component file.

## 5. Environment Setup

### Step 1 — Clone and Install

```bash
git clone https://github.com/zipgrid/zipgrid.git
cd zipgrid
npm install              # Installs all workspaces (hoisted)
cd apps/ai-service
uv sync                  # Installs Python dependencies
cd ../..
```

### Step 2 — Environment Variables

Copy the environment template and fill in values from the team 1Password vault:

```bash
cp apps/web/.env.example apps/web/.env.local
cp apps/ocpp-service/.env.example apps/ocpp-service/.env
cp apps/ai-service/.env.example apps/ai-service/.env
```

**Get values from:** 1Password → Zipgrid Vault → `Development Secrets`

**Critical variables you need immediately:**
```bash
# apps/web/.env.local
DATABASE_URL=                    # From team 1Password (dev Railway DB)
NEXT_PUBLIC_MAPBOX_TOKEN=        # From team 1Password
STRIPE_SECRET_KEY=sk_test_...    # From Stripe dashboard (test mode)
STRIPE_PUBLISHABLE_KEY=pk_test_...
OPENAI_API_KEY=                  # From team 1Password
UPSTASH_REDIS_URL=               # From team 1Password
UPSTASH_REDIS_TOKEN=             # From team 1Password
NEXT_PUBLIC_SUPABASE_URL=        # From team 1Password
NEXT_PUBLIC_SUPABASE_ANON_KEY=   # From team 1Password
```

Never commit `.env.local`. It is in `.gitignore`. Never paste secrets into Slack or code comments.

### Step 3 — Database Setup

```bash
# Run all migrations against the dev database
npm run db:migrate

# Seed with demo data
npm run db:seed:demo

# Verify PostGIS is working
npm run db:verify
# Should output: "✅ PostGIS OK — 12 active listings found"
```

### Step 4 — Start Services

Open 4 terminal tabs:

```bash
# Tab 1: Next.js web app
cd apps/web
npm run dev
# → http://localhost:3000

# Tab 2: OCPP service
cd apps/ocpp-service
npm run dev
# → WebSocket server at ws://localhost:3001

# Tab 3: AI service
cd apps/ai-service
uv run uvicorn main:app --reload --port 8000
# → http://localhost:8000

# Tab 4: OCPP demo charger simulator (optional — for session testing)
cd apps/ocpp-service
node src/simulator/demo-charger.js --chargePointId DEMO-CHARGER-001
```

### Step 5 — Verify Everything Works

```bash
# Run the health check suite
npm run health-check

# Expected output:
# ✅ Web app: http://localhost:3000 — OK
# ✅ OCPP service: ws://localhost:3001 — OK (0 chargers connected)
# ✅ AI service: http://localhost:8000 — OK
# ✅ Database: PostgreSQL + PostGIS — OK
# ✅ Redis: Upstash connected — OK
# ✅ Mapbox: API key valid — OK
```

Log in with demo accounts from `docs/03-technical/3.13-demo-seed-data.md`.

## 7. Domain Rules (Non-Negotiable)

```
RULE 1: Domains do not import from each other's internal files.
  ✅  import { BookingService } from '@/domains/booking'
  ❌  import { validateOverlap } from '@/domains/booking/internal/overlap'

RULE 2: Domain logic lives in src/domains/, not in API routes or components.
  ✅  // In API route: call BookingService.create(params)
  ❌  // In API route: directly write SQL to create a booking

RULE 3: All cross-domain communication uses the event bus.
  ✅  eventBus.publish({ type: 'SESSION_COMPLETED', ... })
  ❌  import { RewardsService } from '@/domains/rewards' (from sessions domain)

RULE 4: All user-facing text lives in i18n files.
  ✅  t('booking.confirmed.title')
  ❌  <h1>Booking confirmed</h1>

RULE 5: All money is in pence (integer). Never floats.
  ✅  pricePerKwhPence: 32  (£0.32)
  ❌  pricePerKwh: 0.32
```

## 8. Git Workflow

```bash
# Always branch from main
git checkout main && git pull
git checkout -b feat/ZIPG-123-booking-cancellation

# Commit convention: Conventional Commits
git commit -m "feat(booking): add cancellation with partial refund"
git commit -m "fix(ocpp): handle reconnect during active session"
git commit -m "test(pricing): add TDD tests for peak surcharge"
git commit -m "docs(api): add wallet topup endpoint"

# Branch naming: [type]/[ticket]-[short-description]
# feat/ fix/ test/ docs/ refactor/ chore/

# Before pushing: run tests locally
npm run test:unit -- --run
npm run lint
npm run typecheck

# Push and open PR
git push origin feat/ZIPG-123-booking-cancellation
# → Open PR against main via GitHub
```

## 9. First PR Checklist

Before submitting your first PR (and every PR thereafter):

```
Code
  □ All new functions have JSDoc headers
  □ No TypeScript `any` used
  □ All new API routes have Zod validation
  □ All new API routes have auth middleware applied
  □ No hardcoded strings — all in i18n files
  □ No cross-domain internal imports
  □ All monetary values in pence (INT)
  □ No unbounded list queries — all paginated

Tests
  □ TDD: business logic tests written before implementation
  □ Unit tests pass: npm run test:unit -- --run
  □ No test coverage regression (check coverage report)
  □ E2E test added for any new user-facing flow

Review
  □ PR description explains: what, why, how to test
  □ Screenshots/videos attached for any UI changes (all 3 themes)
  □ Risk noted: is any existing functionality affected?
  □ Linked to Linear ticket
```

## 10. Common Issues & Solutions

| Issue | Solution |
|-------|---------|
| `PostGIS function not found` | Run `npm run db:migrate` — extension may not be enabled |
| `JWT invalid` in API calls | Check `.env.local` — JWT_ACCESS_SECRET must match between web and test |
| OCPP simulator not connecting | Check OCPP service is running on port 3001 |
| `undefined` in type inference | Check `packages/types/index.ts` — type may not be exported |
| Map not loading | Check `NEXT_PUBLIC_MAPBOX_TOKEN` — must be set in `.env.local` |
| AI service not responding | Check Python env: `uv run uvicorn main:app --reload` in `apps/ai-service/` |
| `Cannot find module '@zipgrid/types'` | Run `npm install` from monorepo root |
| DB migration fails | Check `DATABASE_URL` points to dev DB, not prod |
