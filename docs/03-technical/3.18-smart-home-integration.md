## 1. Why Smart Home Integration Matters

The Zipgrid voice system is phone-first and browser-first. But users increasingly live in multi-device homes:

- **Home Assistant** users already automate their home energy with open-source dashboards
- **Alexa** users already ask their Echo to control smart plugs, heating, and lighting
- **Google Home** users already set routines on their Nest
- **Siri Shortcuts** users already automate iPhone workflows

These users are exactly Zipgrid's ICP — tech-forward EV owners who want maximum automation. Integrating with their existing home ecosystem removes friction and creates platform stickiness that goes beyond the Zipgrid app itself.

**Key insight:** A user who can ask their kitchen Alexa *"Did my car finish charging?"* never needs to open the app. And a homeowner who gets a Home Assistant dashboard notification when a driver arrives never needs to check their phone.

## 2. Integration Architecture

```
                    Zipgrid Platform
                    ┌─────────────────────────────┐
                    │  /api/v1/voice/alexa         │  ← Alexa Skill endpoint
                    │  /api/v1/voice/google-home   │  ← Google Action endpoint
                    │  /api/v1/voice/home-assistant│  ← HA REST API + WebSocket
                    │  /api/v1/voice/wake          │  ← Browser "Hey Zipgrid"
                    └─────────────────────────────┘
                           │
              ┌────────────┼──────────────┐
              │            │              │
         Alexa Echo   Google Home    Home Assistant
         (Skill)      (Action)       (HACS Component)
              │            │              │
         User speaks   User speaks   Automations +
         to Echo       to Nest        Dashboard tiles
```

All three integrations call the same underlying Zipgrid AI agent (`ZipgridAgent.run()`). The surface (Alexa JSON, Google Home JSON, Home Assistant REST) is different; the intelligence is shared.

## 3. Amazon Alexa Skill

### 3.1 Implementation

**File:** `apps/web/src/app/api/v1/voice/alexa/route.ts`

The Alexa skill is a custom skill (not a Smart Home skill) because the primary use case is conversational, not device control.

**Supported Intents:**

| Alexa Intent | Natural language example | Zipgrid Action |
|-------------|-------------------------|----------------|
| `FindCharger` | "Ask Zipgrid to find a charger near Victoria" | `search_listings` tool |
| `BookCharger` | "Ask Zipgrid to book the nearest charger" | `create_booking` tool |
| `SessionStatus` | "Ask Zipgrid what my car is doing" | `get_session` tool |
| `StopCharging` | "Ask Zipgrid to stop charging" | `stop_session` tool |
| `SpendQuery` | "Ask Zipgrid how much I spent this month" | `get_earnings` tool |
| `CheckEarnings` | "Ask Zipgrid what I earned this week" | `get_earnings` tool (host) |
| `StartCharging` | "Ask Zipgrid to charge my car tonight" | `schedule_charging` tool |

**Account linking:** Alexa account linking (OAuth 2.0) maps the Alexa User ID to a Zipgrid User ID. The linking flow is handled in the Alexa app.

### 3.2 Setup for Users

1. Open the Alexa app → Skills → Search "Zipgrid"
2. Enable skill → Tap "Link Account"
3. Sign in with Zipgrid account
4. Say: *"Alexa, ask Zipgrid to find me a charger"*

### 3.3 Example Interaction

```
User:    "Alexa, ask Zipgrid how much my car has charged."
Alexa:   "Your Tesla has charged 26.4 kilowatt hours, reaching 92%.
          Total cost so far is £8.24. Charging is complete."

User:    "Alexa, ask Zipgrid to stop charging."
Alexa:   "Sending the stop command. Shall I confirm?"
User:    "Yes."
Alexa:   "Done. Charging stopped. Session total: £8.24."
```

## 5. Home Assistant — HACS Custom Component

### 5.1 What the Integration Does

This is the most powerful integration — it turns Zipgrid into a first-class Home Assistant device, complete with sensors, binary sensors, and switch entities.

**File:** `apps/web/src/app/api/v1/voice/home-assistant/route.ts`

The component exposes these entities:

| Entity ID | Type | Value |
|-----------|------|-------|
| `binary_sensor.zipgrid_charging` | Binary sensor | on/off — is car charging? |
| `sensor.zipgrid_session_kwh` | Sensor | kWh delivered in current session |
| `sensor.zipgrid_session_cost` | Sensor | Current session cost (£) |
| `sensor.zipgrid_session_soc` | Sensor | Battery SoC % (if available) |
| `sensor.zipgrid_earnings_month` | Sensor | Host earnings this month (£) |
| `switch.zipgrid_charger_{listingId}` | Switch | Start / stop charging remotely |

### 5.2 HACS Component Setup

```yaml
# configuration.yaml — Home Assistant
zipgrid:
  access_token: !secret zipgrid_access_token
  poll_interval: 30   # seconds — how often to refresh sensor states
```

```yaml
# secrets.yaml
zipgrid_access_token: "your-zipgrid-bearer-token-here"
```

After restart, entities appear in Home Assistant automatically.

### 5.3 Home Assistant Automation Examples

**Notify when charging is complete:**
```yaml
automation:
  - alias: "Car charging done"
    trigger:
      - platform: state
        entity_id: binary_sensor.zipgrid_charging
        from: "on"
        to: "off"
    action:
      - service: notify.mobile_app_my_phone
        data:
          message: "EV charging complete. Cost: £{{ states('sensor.zipgrid_session_cost') }}"
```

**Turn off house devices when EV starts charging (demand management):**
```yaml
automation:
  - alias: "EV charging started — reduce demand"
    trigger:
      - platform: state
        entity_id: binary_sensor.zipgrid_charging
        to: "on"
    action:
      - service: climate.set_hvac_mode
        target:
          entity_id: climate.living_room
        data:
          hvac_mode: "off"
```

**Homeowner: notify when a driver arrives:**
```yaml
automation:
  - alias: "Driver arrived at my charger"
    trigger:
      - platform: state
        entity_id: binary_sensor.zipgrid_charging
        to: "on"
    condition:
      - condition: template
        value_template: "{{ state_attr('binary_sensor.zipgrid_charging', 'session_id') is not none }}"
    action:
      - service: notify.alexa_media_kitchen
        data:
          message: "A driver has arrived and started charging."
```

**Start charging at cheapest tariff (Octopus Agile + HA energy dashboard):**
```yaml
automation:
  - alias: "Start EV charging at cheapest rate"
    trigger:
      - platform: template
        value_template: >
          {{ states('sensor.octopus_energy_current_rate') | float < 0.10 }}
    condition:
      - condition: state
        entity_id: binary_sensor.zipgrid_charging
        state: "off"
    action:
      - service: switch.turn_on
        entity_id: switch.zipgrid_charger_YOUR_LISTING_ID
```

### 5.4 Lovelace Dashboard Card

Users who want a Zipgrid tile on their Home Assistant dashboard can use the generic entities card:

```yaml
type: entities
title: EV Charging
entities:
  - entity: binary_sensor.zipgrid_charging
  - entity: sensor.zipgrid_session_kwh
  - entity: sensor.zipgrid_session_cost
  - entity: sensor.zipgrid_session_soc
  - entity: sensor.zipgrid_earnings_month
  - entity: switch.zipgrid_charger_YOUR_LISTING_ID
    name: Start / Stop Charging
```

## 6. Siri Shortcuts

Siri Shortcuts allow iPhone users to trigger Zipgrid actions with a single phrase — without opening the app or navigating any screens.

### 6.1 Shortcuts Available via Zipgrid App

The Zipgrid iOS app exposes these App Intents (iOS 16+ App Intents framework):

| Shortcut | Siri Phrase | Action |
|----------|------------|--------|
| Find Charger | "Find a charger with Zipgrid" | Opens map with voice search pre-activated |
| Session Status | "Ask Zipgrid about my charge" | Returns session status as Siri voice response |
| Stop Charging | "Tell Zipgrid to stop charging" | Sends RemoteStop (confirmation required) |
| Book My Usual | "Book my usual charger with Zipgrid" | Re-books last-used listing at next available slot |

### 6.2 Automation with iOS Shortcuts

Users can chain Zipgrid shortcuts with other iPhone automations:

```
When: I arrive at [Home location]
Then: Run Shortcut "Book My Usual"
     → Zipgrid books home charger for overnight
```

```
When: I connect to [Car Bluetooth]
Then: Run Shortcut "Find Charger" with Zipgrid
     → Map opens voice-first, filtered to current vehicle connector type
```

## 8. What No Competitor Has

Every competitor's voice integration is limited to their own app. None of them expose:
- A Home Assistant component
- Alexa sensor entities (only commands)
- Google Home integration
- Siri Shortcuts with app intents

Zipgrid is the only EV charging platform that integrates natively into a user's existing smart home ecosystem. This creates a category of stickiness — once your Alexa routine says *"has the car finished charging?"*, you don't switch to a competitor app.
