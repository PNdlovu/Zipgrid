## 1. Data Residency Policy

### Confirmed: UK Resident Data Can Be Stored in EU (Amsterdam)

Under the **UK GDPR** (retained EU law post-Brexit), the UK maintains an **adequacy decision** for the EEA (European Economic Area). This means:

- UK personal data can flow freely to EU countries (including the Netherlands — Amsterdam) without additional safeguards
- The reverse is also true under the EU's UK adequacy decision (adopted June 2021, valid until June 2025 — **must confirm renewal status with legal counsel**)
- No Standard Contractual Clauses (SCCs) required for UK→EU transfers
- Railway's `eu-west` region (Amsterdam, Netherlands) is a **lawful destination** for Zipgrid user data

**Hosting decision: Railway `eu-west` (Amsterdam) as primary region for all services at launch.**

This gives:
- Low latency to UK users (Amsterdam ↔ London ~8ms)
- EU data residency compliance for future EU expansion (no data migration needed)
- GDPR-friendly jurisdiction
- Same physical infrastructure serves UK + EU customers

## 2. Authentication & Identity Services

### 2.1 Primary Auth — Custom JWT (Built-in)

Zipgrid uses a custom JWT authentication system built into the Next.js application. This is the primary auth layer and does not depend on a third-party auth provider at runtime — reducing external dependencies for a core security function.

| Component | Implementation |
|-----------|---------------|
| JWT library | `jose` (RFC 7519 compliant, edge-compatible) |
| Access token | HS256, 15-minute TTL |
| Refresh token | RS256, 7-day TTL, rotating |
| Storage (web) | Access token: memory · Refresh token: HttpOnly secure cookie |
| Storage (mobile) | Access token: memory · Refresh token: iOS Keychain / Android Keystore |
| Password hashing | bcrypt, cost factor 12 |
| Session invalidation | Redis blocklist for compromised tokens |

### 2.2 Social Auth Providers

| Provider | Protocol | SDK | Purpose |
|----------|---------|-----|---------|
| **Google** | OAuth 2.0 / OIDC | `next-auth` or `@auth/google` | One-tap Google sign-in |
| **Apple** | Sign in with Apple (SIWA) | `next-auth` + Apple SDK | Required for iOS App Store |

**Note:** Apple Sign-In is mandatory for iOS apps that offer any third-party social login — App Store Review Guideline 4.8. Must be implemented alongside Google.

### 2.3 Identity Verification (KYC)

| Provider | Use Case | Data Residency |
|----------|---------|----------------|
| **Stripe Identity** | Host KYC — ID document + liveness check | Stripe EU infrastructure |
| **Onfido** (backup) | If Stripe Identity unavailable in a market | EU data centres |

Stripe Identity is the primary choice — integrated into Stripe Connect onboarding, minimising additional vendor relationships. Documents are never stored on Zipgrid servers.

### 2.4 Multi-Factor Authentication

| Method | Library | When Enforced |
|--------|---------|--------------|
| TOTP (Authenticator app) | `otpauth` + `qrcode` | Mandatory: all admin accounts · Optional: all users · Mandatory Phase 2: hosts earning > £500/month |
| SMS OTP | Twilio Verify | Phone number verification at registration |
| Email OTP | SendGrid + custom code | Password reset, suspicious login detection |
| Biometric (Face ID / Fingerprint) | iOS LocalAuthentication / Android BiometricPrompt | Available as login shortcut after initial auth |
