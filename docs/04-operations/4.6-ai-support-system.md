## 1. Philosophy

Traditional support is reactive: user has a problem → contacts support → waits → explains context → gets help. This is broken for a real-time platform where a driver may be sitting in a car park with a charger that won't start.

Zipgrid support is **agentic and proactive**:
- The assistant has full context of the logged-in user's account, bookings, and active session
- It answers instantly — no queue, no wait, no ticket number for routine queries
- It resolves most issues autonomously without human involvement
- When human escalation is needed, it hands off with full context pre-filled — the agent never has to ask "what's your booking reference?"

**Speed target:** 80% of support queries resolved by AI in under 30 seconds. Human agent involved for fewer than 20% of contacts.

## 3. Context-Aware Responses

The assistant never gives generic answers. Every response is personalised to the logged-in user's actual data.

### Example — Session Not Starting

**Generic (bad):**
> "Please check your booking confirmation and try scanning the QR code again."

**Context-aware (Zipgrid):**
> "I can see your booking at Sarah's Earlsfield driveway starts at 10am and it's now 10:03am. Your charger (EO Mini Pro, ZIPGRID-LON-0042) last sent a heartbeat 2 minutes ago so it's online. Try scanning the QR code on the charger again. If it still doesn't respond, tap 'Use PIN instead' and enter ZG-8472. Still having trouble? I'll connect you to our team now."

### Example — Billing Query

**Generic (bad):**
> "Your total charge includes energy cost plus any applicable fees."

**Context-aware (Zipgrid):**
> "Your session yesterday at Dev's Manchester café charged you £8.34. Here's the exact breakdown: 19.8 kWh × £0.38/kWh = £7.52, plus 12 idle minutes × £0.07/min = £0.84. There was no peak surcharge as you charged during off-peak hours. Your Wallet was charged — your balance is now £14.66. Does that make sense, or would you like me to look into anything specific?"

### Example — Proactive Support (Before User Asks)

When a session shows an anomaly, the assistant proactively contacts the driver:
> "Hi Marcus — just to let you know, your charging speed has dropped from 11kW to 2.1kW. This can happen when your battery reaches 80% and the car's BMS slows the charge. You should still hit 90% in about 20 minutes. No action needed."

## 4. Support Intents & Resolution Paths

### 4.1 Session Issues

| Intent | AI Action | Human Needed? |
|--------|-----------|--------------|
| "Charger won't start" | Check OCPP status → try RemoteStart → give PIN → offer technician | Only if OCPP fault detected |
| "Session stuck" | Check live session → try RemoteStop → manual close if needed | If RemoteStop fails |
| "Charger stopped unexpectedly" | Pull OCPP stop reason → explain in plain English | If reason unclear |
| "Wrong kWh shown" | Pull raw meter values → compare → explain or issue partial refund | If significant discrepancy |

### 4.2 Billing Issues

| Intent | AI Action | Human Needed? |
|--------|-----------|--------------|
| "Why was I charged X?" | Pull transaction breakdown → explain each line item | Only if error found |
| "I was overcharged" | Compare session data to booking price snapshot → issue refund if error < £50 | If > £50 or disputed |
| "Refund my booking" | Check cancellation policy → calculate eligible refund → issue automatically | If policy edge case |
| "Where's my payout?" (host) | Check payout status + bank account → give ETA | If Stripe issue detected |

### 4.3 Account Issues

| Intent | AI Action | Human Needed? |
|--------|-----------|--------------|
| "Can't log in" | Trigger password reset email | Only if account locked |
| "KYC failed" | Explain reason → guide resubmission → give retry count | If 3+ failures |
| "Update my bank account" | Link to Stripe Connect re-onboarding | Never — Stripe handles |
| "Delete my account" | Confirm intent → initiate GDPR erasure workflow → confirm timeline | Never — automated |

### 4.4 Listing / Booking Issues

| Intent | AI Action | Human Needed? |
|--------|-----------|--------------|
| "Host isn't responding" | Check host response rate → send reminder to host → offer rebooking | If < 2hrs to session |
| "Listing is different from photos" | Create incident report → issue refund → flag listing for review | Always (trust issue) |
| "Gate code doesn't work" | Re-send access instructions → contact host → offer emergency mode | If host unreachable |
| "I want to report a problem" | Open Resolution Centre flow → capture evidence | Always logged |

### 4.5 Knowledge Queries

| Intent | AI Action | Human Needed? |
|--------|-----------|--------------|
| "How do idle fees work?" | RAG → knowledge base answer | Never |
| "What's my cancellation policy?" | RAG → pull user's specific booking policy | Never |
| "Is my charger covered by insurance?" | RAG + check user's listing safety score + insurance status | Never |
| "How do I set up peak pricing?" | RAG → step-by-step guide | Never |

## 5. Assistant Persona & Tone

```
Name: Zipgrid Assistant (no cutesy name — professional but warm)
Tone: Direct, knowledgeable, efficient, British English
Response length: As short as possible. No padding.
Never: Use jargon without explanation. Say "as per our records". Ask redundant questions.
Always: Use the user's name. Reference actual data. Offer the next step.

Example tone calibration:
✅ "Your session ended at 11:47am with 23.1 kWh delivered. Receipt sent to your email."
❌ "Thank you for reaching out to Zipgrid Support. We have reviewed your query and can confirm that your charging session was successfully completed on the aforementioned date."
```

## 6. Handoff to Human Agent

When AI cannot resolve the issue, it hands off cleanly:

```typescript
/**
 * @description Human handoff payload — everything the agent needs, pre-filled.
 * Never make a human agent ask "what's your booking reference?"
 */
type HumanHandoffPayload = {
  userId:           string
  userName:         string
  userEmail:        string
  issueCategory:    string
  aiSummary:        string    // 2-3 sentences: what the user said, what AI tried, why it's escalating
  suggestedAction:  string    // AI's recommendation for the human agent
  urgency:          'low' | 'medium' | 'high' | 'critical'
  contextSnapshot:  {
    activeBooking:  Booking | null
    activeSession:  Session | null
    recentBookings: Booking[]
    openDisputes:   Dispute[]
    walletBalance:  number
  }
  chatHistory:      Message[]
}
```

The human agent opens the Intercom conversation and sees:
1. AI-generated summary at the top
2. Full chat transcript below
3. User's account sidebar with all context
4. Suggested next action
5. Quick-action buttons: Issue Refund | Cancel Booking | Create Incident | Escalate to Manager

## 7. Voice Support Integration

The support assistant is also accessible via voice:

- Driver says: *"Hey Zipgrid, my charger stopped"*
- Voice intent parsed: `{ intent: "session_issue", sub_intent: "session_stopped_unexpectedly" }`
- Context loaded: active session data
- AI responds via TTS: *"Your session at Dev's café stopped 4 minutes ago. The charger reports EVDisconnected — your car has unplugged itself. Your final charge was 18.7 kWh costing £7.10. Would you like me to end the session and process payment?"*

Voice support follows the same resolution paths as text — same tools, same context, same escalation logic.
