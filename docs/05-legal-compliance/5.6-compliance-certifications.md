## 2. Cyber Essentials (Launch Requirement)

### What It Is
UK government-backed certification that verifies five basic security controls:
1. Firewalls and routers
2. Secure configuration
3. Access control
4. Malware protection
5. Patch management (keeping software up to date)

### How to Obtain
- **Self-assessment version:** Complete online questionnaire via an NCSC-approved certifying body
- **Cost:** £300–£500 for basic certification
- **Time:** 1–2 weeks once controls are in place
- **Certifying bodies:** IASME Consortium, IT Governance, QG Management Standards

### Zipgrid Controls Already in Place

| Control | Implementation |
|---------|--------------|
| Firewall | Cloudflare WAF + Railway network isolation |
| Secure configuration | Railway environment variables, no default credentials |
| Access control | RBAC + MFA on admin accounts + RLS on database |
| Malware protection | Snyk dependency scanning + GitHub CodeQL |
| Patch management | Dependabot automated PRs + weekly audit |

**Cyber Essentials Plus** (higher tier): adds independent testing by a certifier. Recommended for Year 2 when enterprise SMB clients start requiring it.

## 3. SOC 2 Type I (Month 12 Target)

### What It Is
An audit report by a CPA firm confirming that Zipgrid's security controls were **designed** correctly at a specific point in time. Covers the five Trust Service Criteria: Security, Availability, Confidentiality, Processing Integrity, Privacy.

### Why We Need It
- US enterprise clients and fleet operators require it
- Investors and acquirers expect it during due diligence
- Demonstrates operational maturity to insurance underwriters

### How to Obtain

**Step 1 — Compliance automation (Month 1):**
- Deploy **Vanta** (already in our tech stack)
- Vanta auto-collects evidence from Railway, GitHub, Stripe, Google Workspace
- Shows current compliance gaps on a live dashboard

**Step 2 — Gap remediation (Months 1–9):**
Common gaps Vanta will surface:
- Vendor security assessments (annual review of all 22 third-party services)
- Access reviews (quarterly review of who has admin access)
- Security awareness training (all team members annually — KnowBe4 or Curricula)
- Incident response testing (tabletop exercise annually)
- Background checks (for engineering + finance team members)
- Asset inventory (all devices and services documented)

**Step 3 — Auditor engagement (Month 9–10):**
- Engage a CPA firm with SOC 2 experience
- Recommended auditors: Prescient Assurance, Johanson Group, Sensiba
- Cost: £8,000–£18,000 for Type I audit

**Step 4 — Readiness assessment (Month 10):**
- Auditor reviews Vanta evidence
- Identify any remaining gaps
- Remediate before the observation period

**Step 5 — Type I report issued (Month 12):**
- Auditor issues SOC 2 Type I report
- Valid for sharing with prospects and investors under NDA

### SOC 2 Type II (Month 18–24)

Type II covers the same criteria but over a 6–12 month observation period (controls must be consistently followed, not just in place). Follow-on engagement with same auditor. Cost: £12,000–£25,000.

## 4. ISO 27001 (Month 24–36)

### What It Is
International standard for Information Security Management Systems (ISMS). More comprehensive than SOC 2 — covers governance, risk management, and a full PDCA (Plan-Do-Check-Act) cycle.

### Why We Need It (Phase 3)
- EU enterprise clients and government contracts often require it
- Strengthens the Series A investment case
- Required for some insurance products
- Positions Zipgrid for public sector and utility partnerships

### How to Obtain

**Step 1 — Gap assessment (Month 18):**
- Engage an ISO 27001 consultant (Cogito Group, IT Governance, BSI)
- Cost: £3,000–£8,000 for initial gap assessment
- Produces a Statement of Applicability and remediation roadmap

**Step 2 — ISMS implementation (Months 18–30):**
- Implement the 93 controls from ISO 27001:2022 Annex A
- Most are already in place via Vanta + existing security controls
- New requirements: formal risk register review, supplier management policy, asset classification

**Step 3 — Internal audit (Month 30):**
- Run internal audit against ISO 27001 requirements
- Document corrective actions

**Step 4 — Certification audit (Month 33–36):**
- Stage 1: Document review (off-site)
- Stage 2: On-site audit of controls
- Certifying bodies: BSI Group, Lloyds Register, Bureau Veritas
- Cost: £6,000–£15,000 for certification audit

**Step 5 — Certificate issued + annual surveillance audits:**
- ISO 27001 certificate valid 3 years with annual surveillance audits
- Cost: £2,000–£4,000/year for surveillance

## 5. Secrets & Keys Management

### Principle: Zero Secrets in Code

All secrets must be stored in a secrets manager — never in source code, `.env` files committed to git, Slack messages, or documentation.

### Current Setup (Development)

| Secret Type | Storage | Access |
|-------------|---------|--------|
| Development API keys | Railway environment variables | Engineering team via Railway dashboard |
| Production API keys | Railway environment variables (prod) | CTO + founder only |
| Team shared credentials | 1Password Teams vault | Named team members only |
| Stripe API keys | Stripe dashboard → Railway env | CTO only for production |
| Database connection strings | Railway environment variables | Service accounts only |
| Signing keys (JWT) | Railway environment variables | Rotated quarterly |

### Key Rotation Schedule

| Key/Secret | Rotation Frequency | Method |
|-----------|-------------------|--------|
| JWT signing keys (HS256/RS256) | Every 6 months | Generate new, deploy both temporarily, deprecate old |
| Stripe API keys | Every 12 months or on suspected compromise | Stripe dashboard → generate new → update Railway |
| Database passwords | Every 12 months | Railway managed rotation |
| OpenAI API key | Every 6 months or on breach | OpenAI dashboard → revoke → create new |
| OCPP device credentials | Per charger — on pairing | Generated at pairing, never reused |
| Admin account passwords | Every 6 months | 1Password enforces complexity + rotation |

### Production Secrets Governance

```
WHO can access production secrets:
  CTO: all production Railway variables
  Founder: Stripe production keys, database connection strings
  On-call engineer: read-only access to non-sensitive env vars

WHO cannot access production secrets:
  All other engineers: staging + dev only
  External contractors: never
  AI coding assistants: never (do not paste secrets into AI chat)

HOW new secrets are added:
  1. CTO creates secret in Railway production environment
  2. CTO notifies affected engineer that variable is available
  3. Variable name (not value) documented in .env.example
  4. Change logged in audit trail
```
